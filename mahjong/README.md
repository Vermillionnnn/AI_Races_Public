# 麻将 debug

一个虚构的高中编程社团项目：几位学生各写了日本立直麻将后端的一个模块，指导老师为了拼起来又打了一层临时补丁，能跑，但打起来“手感怪怪的”。选手扮演老师请来帮忙的人，只凭老师在聊天框里的口述开工，没有现成的规则文档。社团项目里的学生代码和老师补丁也是由不同的 AI 模型扮演学生和老师写出来的。

| 轮次 | 任务 | 成绩 |
|---|---|---|
| [`round-1/`](round-1/) | 45 分钟内：找 bug 并修好、把后端适配到程序员朋友写好的牌桌页面（页面别大改）、给每位学生和老师写反馈、写一份新手规则文档、把几处规则分歧做成开关 | [`round-1/results.md`](round-1/results.md) |
| [`round-1.5/`](round-1.5/) | round-1 评完后，把各家自己挂掉的问题转成学生和程序员朋友的口头试玩反馈（不给用例和牌山），在原会话里不限时再修一轮。round-1 已全对的两家没有参加 | [`round-1.5/results.md`](round-1.5/results.md) |

## 目录

| 目录或文件 | 内容 |
|---|---|
| `player-kit/` | 选手包，和发给选手的逐字相同：6 份学生模块、老师补丁 `server_patch.py`、程序员朋友写的牌桌页面和接口说明（`frontend/`）、老师整理的分工约定（`docs/`） |
| `judge/` | 判分程序：已知 bug 的复现用例（50 个）、随机算点对拍、规则变体一致性核查，以及各项结果的汇总。全部通过牌桌页面用的 HTTP 接口调用选手程序，用法见 `judge/README.md` |
| `reference/` | 我们另写的参考实现和参考规则，对拍的标准答案由它给出 |
| `<轮次>/开场消息.md` | 在聊天框里发给选手的消息（开赛、报时、收尾；round 1.5 是各家的问题列表），附我们怎么发的说明 |
| `<轮次>/submissions/<选手>/` | 选手交的整份目录，原样保留；另加 `对话框输出.md`：选手在聊天界面回复的文字，不含思考过程和工具调用 |
| `<轮次>/results.md` | 成绩和复核说明；round-1 另有文字评分的过程和提示词 |

## 自己跑一遍

只用 Python 标准库。在本目录的上一级（仓库根目录）运行：

```
python3 mahjong/judge/run.py                      # 复现用例：学生原件和 round-1 全部提交
python3 mahjong/judge/run.py kimi-k3-1-pro@r1.5   # 指定选手；round 1.5 的版本加 @r1.5
python3 mahjong/judge/crosscheck.py -n 2400 --seed 2026   # 算点对拍（正式一轮的参数）
```

测试会按 `python3 server.py --port N` 在本机起选手的后端，需要能监听本地端口。

这里是留档，脚本是从我们自己的目录原样搬过来的，个别地方（比如参考实现找牌桌页面的路径、文档里指向未公开文件的链接）还按原来的目录写，不保证在每个人的环境里都能直接跑通，需要的话照着改一下路径。
