## 1. 给 `250207`（社长 · `game.py`）的反馈

整体流程框架很完整，轮次推进、立直一发、振听判定、流局连庄的思路都很清晰，自测用例也写得很好。但因为《接口说明》出来之前自己先定了一套内部约定，加上部分规则用了 TODO 简化，联调时主要的问题集中在这里：

### 发现的 Bug 与遗漏
1. **牌山配牌顺序和王牌位置与《接口说明》不一致**
   - `start_round()` 里用 `seat = (self.oya + k) % 4` 发牌，导致换庄后 `wall[0:13]` 发给了庄家而不是固定物理座位 0。按约定无论谁当庄，`wall[0:13]`、`[13:26]`、`[26:39]`、`[39:52]` 都应固定发给座位 0–3。
   - `dead_wall` 原本自己定了 `[0:4]` 为岭上牌、宝牌/里宝牌交错放置；而《接口说明》规定 `wall[122:127]` 为宝牌指示牌、`wall[127:132]` 为里宝牌指示牌、`wall[132:136]` 为岭上牌。这会导致指定 `wall` 测试时宝牌和岭上牌全部错位。
2. **与 `yaku.py` / `fu.py` 对接传参遗漏与拼写错**
   - **地和失效**：`_make_state()` 传的是 `'chihou'`，而 `yaku.py` 读的是 `'chiihou'`，导致地和永远无法判定。
   - **暗杠信息没传过去**：`calc_yaku()` 需要 `state['ankan_indices']`，`calc_fu()` 需要 `an_gang` 参数，但都没有传。结果玩家一旦暗杠，不仅结算时被当成明杠（符数减半、丢门前加符、丢三暗刻/四暗刻），连 `_win_ok()` 判有役时也误以为破了门清，导致仅靠门清自摸或三暗刻的牌直接“不能和”。
   - **里宝牌混进了普通宝牌**：`_score_one()` 里 `dora_list(with_ura=...)` 把里宝牌直接塞进 `dora` 列表，没有放到 `state['ura_dora']`，结算明细里里宝牌全显示成了“宝牌”。
3. **规则功能缺失与手感异常**
   - **缺少抢杠（Chankan）**：`_kakan()` 加杠直接摸岭上，没有给其他玩家荣和（抢杠）的机会。另外国士无双抢暗杠也建议一并支持。
   - **缺少四杠散了**：`kan_seats` 已经记了谁开杠，但 `_after_discard_pass()` 没有判定；两人及以上合计开到第 4 个杠时，该杠牌者打出一张若无人荣和（且该张不能再被吃碰），应触发 `四杠散了` 流局。
   - **明杠/加杠的杠宝牌翻开时机**：现在暗杠和明/加杠都在杠完瞬间立刻翻宝牌；按规范，暗杠立刻翻，而大明杠、加杠应等打出那张牌且无人荣和之后再翻——尤其要注意**打出的那张牌被人吃、碰或再次明杠时**也算“无人荣和”，若只把翻宝牌写在 `_after_discard_pass()` 里会被鸣牌分支提前 `return` 跳过，导致新宝牌指示牌一直翻不出来。应在 `_resolve_calls()` 确认无人荣和后统一调用 `_reveal_pending_dora()`。
   - **终局和了止同分判定与剩余立直棒 `delta`**：
     - All Last 庄家和牌连庄判断“是否第一名（和了止）”时，不能只看 `self.scores[self.oya] == max(self.scores)`；按起家顺位规则，同分时起家（座位更小者）排在前面，应按 `(score, -seat)` 找出真正的第一名座位再比 `self.oya == top_seat`（例如东 4 局座位 3 的庄家与起家座位 0 同分，庄家不是第一，应当继续连庄打下去）。
     - 对局以流局结束且场上仍有未收走的立直棒时，把供托加给第一名 `self.scores[top]` 的同时，也必须把这笔 `kyotaku * 1000` 计入 `result['delta'][top]`，否则结算弹窗里“变化”和“现在”的分数对不上。
   - **红五碰牌选项缺失**：`_pick_pon_tiles()` 当手牌有 `0m, 5m, 5m` 时强行只给一种带红五的碰；按《接口说明》应把 `['0m', '5m']` 和 `['5m', '5m']` 两个选项都列出来由玩家自己选。
   - **副露数据缺字段**：`melds` 没有记录 `called_tile`（前端用来决定哪张牌横置），且暗杠把 `'from'` 写成了自己座位号（前端要求暗杠的 `from` 和 `called_tile` 都为 `null`）。
   - **`get_visible()` 重复统计**：别人被鸣走的牌仍留在 `rivers[s]`（只是标了 `called=True`）同时又在鸣牌方的 `melds` 中，导致 `get_visible()` 算了两次；而且把自己的 `melds` 也塞了进去，和 `tenpai.py` 又扣了一遍，听牌剩余张数严重偏少。
   - **未记录 `tsumogiri` 与对局 `events`**：河牌和前端日志都无法区分手切和摸切，也无法展示出牌历史。
   - **食替边界与立直暗杠严密性**：当吃/碰后手牌全变成食替禁止牌时，原代码用 `or discards` 反而放行了食替，应该在生成吃/碰选项时直接过滤掉会导致无牌可打的组合；立直后暗杠除检查听牌种类不变外，还需防止改变原手牌面子构成（送りカン，如 `111222333m` 暗杠 `1m`）。
   - **缺半庄战（`hanchan`）与 4 个规则开关支持**，`make_wall()` 在无赤宝牌开关关闭时仍会生成 `0m/0p/0s`。
   - **独立调用 `calc_yaku` 与 `calc_fu` 违背高点法**：遇到有多种拆法的牌型（例如 `23455m...` 荣 `2m`）会拼出“平和 + 40 符”的矛盾结果，应联合同一套拆法按点数最高者结算。
   - **小笔误**：`do_action` 里碰牌找不到选项时报错 `'没有这个吃法'`。

### 改进建议
已按照《接口说明》修正牌山与王牌下标、补全抢杠/四杠散了/杠宝牌时机/半庄战/规则开关/事件流/高点法联合算分，建议后续重点补写针对指定牌山的单元测试。

## 2. 给 `260331`（`fu.py`）的反馈

`fu.py` 的代码注释非常详细，思路清晰，对平和自摸 20 符 / 荣和 30 符、七对子 25 符、副露平和型 30 符、二杯口不按七对子算、嵌张/边张/单骑以及 13/14 张手牌兼容都处理得很准确，自测覆盖也很到位。

### 发现的问题与建议
1. **最大的问题是“独自取最大符”会与 `yaku.py` 拆法打架（破坏高点法）**
   - 你在注释里也敏锐地意识到了这个问题。当一副手牌同时有两种拆法时（比如 `23455m 456p 789s 234s` 荣 `2m`，或者 `123345m...` 荣 `3m`）：
     - `yaku.py` 会选能凑成**平和**（两面听）的拆法给 1 番；
     - 而 `fu.py` 只看符最大，选了单骑（`22m` 雀头）或嵌张的拆法给 40 符；
     - 两者拼起来就变成不可能存在的**“平和 40 符”**！还有像 `111222333m 456p 77s` 自摸 `4p`，三暗刻+自摸（3 番 40 符）点数高于平和+一杯口+自摸（3 番 20 符），必须让番和符使用**同一种拆法**算完点数再取最大。
   - **修改方式**：保留 `calc_fu()` 原接口的同时，新增一个按指定拆法 `(pair, hand_groups, wait)` 算符的函数 `calc_fu_decomp()`，供 `game.py` 联合 `yaku.py` 执行高点法。
2. **连风牌雀头写死 4 符，未预留规则开关**
   - `que_tou_fu()` 目前固定场风=自风时加两次变成 4 符。为适配前端的 `renpu_fu` 开关（2 符 / 4 符），在函数末尾增加了可选参数 `renpu_fu=4`（不破坏原有参数顺序）。
3. **暗杠需要 `an_gang` 参数配合**
   - 原本你预留了 `an_gang` 参数是正确的，但 `game.py` 调用时没有传，导致所有暗杠在算符时全被当成明杠、还丢了门前加符。联调时记得主动确认上游有没有把扩展参数传到位。

## 3. 给 `250118`（`yaku.py`）的反馈

`yaku.py` 写得非常整齐干净，役种覆盖面很广（连普通役、役满、双倍役满、复合役满、门清暗杠不破门清、荣和刻子不计暗刻、国士十三面、纯正九莲等都做出来了），整体质量很高。

### 发现的 Bug 与改进点
1. **地和键名拼写与 `game.py` 不一致**
   - `tile_yakuman()` 里读的是 `state.get("chiihou")`，而 `game.py` 传的是 `'chihou'`，导致地和一直无法触发。两处约定一定得核对拼写（已同时兼容两个键名）。
2. **`win_tile` 校验在红五归一化之前执行**
   - `calc_yaku()` 第 354 行先判断 `win_tile not in hand`，第 363 行才调用 `normal_tile(win_tile)`。如果手牌里有 `'0p'` 而 `win_tile` 传了 `'5p'`（或反之），会直接判定为不和牌返回 `([], 0)`。应先归一化再校验。
3. **返回格式丢掉了每个役的番数，也没区分真役满与累计役满**
   - `calc_yaku()` 原先只返回役名列表和总番数，还把宝牌数量拼在名字里（如 `"宝牌3"`）。这导致 `server_patch.py` 只能用字典去瞎猜每项几番——结果把你写的 `"两立直"`（字典写的是 `'双立直'`）猜成 1 番、把副露减番役（混一色、清一色、三色、一气等）和宝牌张数全部猜错！
   - 同时，按《接口说明》要求，真役满时 `yakuman` 为倍数（1、2…），而**累计役满**（>=13 番但非役满牌型）`yakuman` 必须为 `0` 以便前端照常显示符和番。
   - **修改方式**：保留 `calc_yaku()` 原签名兼容老调用，同时提供 `calc_yaku_candidates()` / `calc_yaku_detail()` 返回每个役的 `(役名, 番数)`（宝牌名称统一用 `"宝牌"`、`"赤宝牌"`、`"里宝牌"`，番数写张数）以及精确的 `yakuman` 倍数，并支持和 `fu.py` 联动执行高点法。
4. **未接入规则开关 `kuitan` 和 `aka_dora`**
   - `yaku_tanyao()` 目前默认总是允许食断（副露断幺九），`dora_yaku()` 也默认必算赤宝牌。已通过可选 `rules` 参数（及 `state` 兜底）接入开关：关闭 `kuitan` 时仅门清可计断幺九；关闭 `aka_dora` 时不计赤宝牌。

## 4. 给 `260409`（`score.py`）的反馈

点数查表和公式兜底结合得很好，满贯以上的分档、本场（+300 / +100）和立直棒（+1000）的加减都算得准确，七对子 25 符不进位也专门处理了。

### 发现的 Bug 与改进点
1. **切上满贯写死且查表缺少 `(3, 60)` 与 `(4, 30)`**
   - 你按 M 联赛规则把 4 番 30 符、3 番 60 符直接当成满贯，在表里跳过了这两档。但现在项目需要提供 `kiriage_mangan`（切上满贯）规则开关：当开关为 `False` 时，这两档应分别算 7700 / 11600（子/庄荣）与 2000-3900 / 3900 ALL（自摸）。已在表和 `_get_limit_rank()` 中补齐开关支持。
2. **未支持多倍役满（如双倍役满）与高符基本点封顶**
   - `yaku.py` 和《接口说明》都支持双倍役满（例如四暗刻单骑、大四喜等，26 番，对应 64000 / 96000 点）以及复合役满；但 `score.py` 里凡是 `han >= 13` 一律按单倍役满算。现已增加 `yakuman` 倍数参数，真役满按倍数放大，累计役满（`yakuman=0` 且 `han >= 13`）维持 1 倍役满点数。
   - 另外当 `han <= 4` 走基本点兜底公式时，原代码没有对 `base` 做 `min(..., 2000)` 封顶；万一遇到 2 番 130 符以上的极罕见牌型会算出超过满贯的分数，已补齐封顶判定。
3. **返回值格式与《接口说明》中的 `points` 要求**
   - `calc_score()` 返回 dict 是合理的，但和 `game.py` 约定的 `(得分, 各付)` 不一致，导致 `server.py` 要单独打补丁。此外结算弹窗需要展示“这手牌本身值多少点（不含本场和供托）”，调用 `calc_score(..., honba=0, kyotaku=0)` 即可单独拿到。

## 5. 给 `260522`（`tenpai.py`）的反馈

`tenpai.py` 整体逻辑非常清楚，一般形回溯拆面子、七对子（正确排除了四张同牌）、国士无双、红五统一归并、以及“不能自持 4 张再听第 5 张”的细节都考虑到了。

### 发现的问题与改进点
1. **听牌剩余张数（`left`）与 `game.py` 之间存在重复扣减**
   - `get_waits()` 内部把 `hand`、`melds` 和 `visible` 里的牌全部扣了一遍；但 `game.get_visible()` 把场上所有人的副露（包括你自己的副露）以及未从牌河移除的被鸣牌全都塞进了 `visible`。结果就是：**自己的副露被扣了两次，别人从牌河鸣走的牌又多扣一次**，听牌提示经常显示“还剩 0 张”而实际牌山还有 1~2 张。
   - **修改方式**：明确约定 `visible` 只传“未在自己 `hand`/`melds` 中出现的场上可见牌”（他人副露 + 未被鸣走的牌河 + 宝牌指示牌），`tenpai.py` 里加上说明和牌面合法性校验，避免越界或无效字符串导致误判。
2. **出牌前听牌提示（`discard_hints`）在特定牌型下会多算 1 张**
   - `discard_hints()` 里用 `rest = hand[:i] + hand[i + 1:]` 调用 `get_waits(rest, melds, visible)` 时，刚试着打出去的那张 `tile` 既已经从 `rest` 里删掉了，又还没有进到牌河 `visible` 里。如果你打出 `tile` 后刚好也听这种牌（比如 `22345m` 打 `2m` 听 `2m/5m`，或 `123s` 打 `1s` 听 `1s/4s`，或打掉红 `0m` 听 `5m`），`left` 就会凭空多出 1 张。调用时传入 `visible + [tile]` 即可修正。
3. **前端展示与打牌提示配合细节**
   - 在 `discard_hints()` 中，手上有 `0m` 和 `5m` 时能正确分别列出提示（符合前端接口规范）；在 `server.py` 封装时还需按当前合法可打牌列表过滤（比如发生食替禁止或立直后，不能打的牌不应画蓝色听牌下划线）。

## 6. 给 `250226`（`server.py`）的反馈

用标准库 `http.server` 实现零外部依赖、写好 CORS 跨域头和 JSON 错误兜底、以及主动用兼容层去适配 `score.py` 的不同返回格式，这些工程意识都很好！

### 发现的问题与改进点
因为写作时还没有看到前端同学的《接口说明》，所以这一版和前端协议几乎对不上，指导老师才临时写了 `server_patch.py` 救急。主要差距在于：
1. **启动命令与静态页面服务未按上线规范实现**
   - 线上部署固定执行 `python3 server.py --port 8000`，但原 `server.py` 不支持 `--port` 参数（默认端口也写成了 `5000`），且 `GET /` 只返回一段 JSON 文本，没有把 `frontend/index.html` 发送给浏览器。
2. **返回 JSON 字段与《接口说明》严重不匹配**
   - 缺少 `version`、`game_id`、`waiting_for`、`rules`、`events`、`wall_left`、`viewer`、`turn` 等必需字段。
   - `phase` 用了 `game.py` 内部的 `'discard'/'call'/'end'`，而非约定的 `'playing'/'round_end'/'game_end'`；`round` 和 `players[i]` 字段名也没有按说明映射。
   - `legal_actions` 未将多个 `chi`/`pon` 合并为 `options`、未区分 `ankan`/`kakan`/`minkan`；`hints.waits` 给了字典而不是按牌序排列的 `[{tile, left}]` 数组，也缺少 `furiten`。
3. **缺少多局管理、四人测试模式与参数透传**
   - 原来只维护单个全局 `current_game` 和单个人类座位 `DEFAULT_SEAT=0`；需要支持每次 `new_game` 分配新的 `game_id`（允许一个进程连续开多局）、支持 4 个座位各自 `human`/`bot` 配置、支持 `length` 和 `rules`、透传 `tsumogiri`、校验合法性并在出错时返回 HTTP 400 + `{"error": ...}`。
4. **老师临时补丁 `server_patch.py` 中暴露的残留问题**
   - 补丁也遗漏了 `rules`、`events`、`tsumogiri`、`called_tile`、`game_id` 递增和 `length`；并且用 `YAKU_HAN` 表硬猜各役番数、用 `delta` 代替手牌点数 `points`、用 `han >= 13` 误判累计役满。现在已全部合入正式版 `server.py` 中彻底解决。
