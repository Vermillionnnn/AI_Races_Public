下面按问题逐一说明根因和给对应同学的修改方式：
1. 明杠后打出的牌被别人碰（或吃/明杠），新宝牌指示牌一直没翻
- 定位：game.py 的 _resolve_calls() 与 _after_discard_pass()（涉及 250207）。
- 原因：原先把 self._reveal_pending_dora() 仅放在 _after_discard_pass() 里；而当有人在 _resolve_calls() 中选择 pon、chi 或 minkan 时，会直接调用 _call_meld() 并 return，跳过了 _after_discard_pass()，导致 pending_kan_dora 一直留到很久以后甚至整局结束都没翻开。
- 怎么改：在 _resolve_calls() 中确认 rons（及抢杠）都未触发、即“打出的牌无人荣和”之后、执行 pon/kan/chi 分支之前，就立刻调用 self._reveal_pending_dora()；这样无论没人鸣牌还是被人吃碰杠，新杠宝牌都会立刻翻开。
2. All Last 庄家和牌且与起家同分时误判终局
- 定位：game.py 的 _check_game_over()（涉及 250207）。
- 原因：判断和了止时只写了 top = max(self.scores) 和 self.scores[self.oya] == top。当座位 3（庄家）和座位 0（起家）同分时，两者分数都等于 top，误把庄家当成了第一名直接结束；而实际按起家顺位规则，同分时座位号靠前（-s 更大）的起家才是第一名，庄家只排第二。
- 怎么改：沿用结算排名一样的顺位比较法，先算出第一名座位 top_seat = max(range(4), key=lambda s: (self.scores[s], -s))，再用 self.oya == top_seat and self.scores[top_seat] >= RETURN_POINTS 判断是否满足和了止。
3. 终局时场上剩余立直棒加给了第一名，但结算 delta 里缺少这笔点数
- 定位：game.py 的 _end_round()（涉及 250207）。
- 原因：当最后一局以流局结束且场上仍有 self.kyotaku > 0 时，if self.game_over: 分支只做了 self.scores[top] += self.kyotaku * 1000，忘了把同样这笔点数加到 result['delta'][top]，造成结算界面里“上局分数 + 变化 ≠ 现在分数”。
- 怎么改：在 _end_round() 里给 self.scores[top] 加上 leftover = self.kyotaku * 1000 的同时，同步执行 delta[top] += leftover（并注意拷贝传入的 delta），使 scores、delta 与 1000 × 供托根数 完全一致。
4. 打牌前听牌提示（鼠标悬停）的剩余枚数偶尔多 1 张
- 定位：tenpai.py 的 discard_hints()（涉及 260522）。
- 原因：计算“打出 tile 后还剩几张听牌”时，rest = hand[:i] + hand[i + 1:] 把待打的 tile 从手里删掉了，但此时 tile 还没有进牌河，get_waits(rest, melds, visible) 并不知道这张 tile 即将变成明牌（进自己牌河）。一旦打出的 tile 与所听牌是同一种牌（如 123s 打 1s 听 1s/4s、22345m 打 2m 听 2m/5m，或打红 0m 听 5m），left 就会多算 1 张。
- 怎么改：在 discard_hints() 中把调用改为 get_waits(rest, melds, visible + [tile])，把试着打出去的那张牌一并算进可见牌扣减。
