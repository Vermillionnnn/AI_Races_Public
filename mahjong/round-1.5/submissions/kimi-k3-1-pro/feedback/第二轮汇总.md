# 第二轮问题定位与改法

详细说明已分别追加到对应学号文件。本表用于快速转交。

| 问题 | 根因 | 改法与正确结果 | 主要负责 |
|---|---|---|---|
| 平和荣和、自摸都多 10 符 | 番采用两面解释，符却另选单骑解释 | 番符固定同一拆法和等待位置；荣和 30 符，自摸 20 符 | 260331、250118、250207 |
| 一杯口＋混全点数高一档 | `111222333m` 的顺子拆法配上了刻子拆法的高符 | 联合返回 yaku/han/fu；3 番 40 符，闲家荣和 5200，不是 50 符 6400 | 260331、250118、250207 |
| 只有抢杠不能和 | 抢杠必须是独立的 1 番状况役，且加杠状态要保留到结算 | 不限制门清或其他役；补门清及带副露两种回归，均可和 | 250118、250207 |
| 相同摸牌使手牌没排好 | 删除 drawn 时删了旧副本，末尾新副本留在手牌中 | API 分离 drawn 后重新排序，结算 hand 同样排序 | 250226 |
| 多副露吃后全是食替禁牌 | 只在吃完后过滤，且 `or discards` 又放开全部禁牌 | 生成吃/碰选项时模拟剩余手牌，无合法舍牌就不提供该选项 | 250207 |
| 宣言牌被和仍显示立直 | pending 已变成立直标记，但荣和分支未撤销 | 有 ron 时清 `riichi/double_riichi/ippatsu/pending`；不收立直棒 | 250207 |
| 立直后提示其他打牌 | hints 没服从 legal_actions | 立直状态 `hints.discards={}`，只保留合法摸切操作 | 250226 |
| 终局供托只进分数不进 delta | 第一名的供托奖励漏写结算数组 | 同时更新 `scores[top]`、`delta[top]`、`result['delta']` | 250207 |
| 打牌前剩余数多一张 | 模拟舍牌已从 hand 删除，却没加入 visible | 每次 `get_waits` 使用 `list(visible)+[tile]`；1s/4s 例为 3/4 | 260522 |

联合结算的新接口：

```python
yaku, han, fu = calc_hand_details(
    hand, melds, win_tile, is_tsumo, bakaze, jikaze,
    dora, state, rules=rules,
)
```

`calc_yaku`、`calc_yaku_detailed`、`calc_fu` 的旧调用形式仍保留。游戏结算 `_score_one` 已改用联合接口，避免重复枚举时再次选错拆法。
