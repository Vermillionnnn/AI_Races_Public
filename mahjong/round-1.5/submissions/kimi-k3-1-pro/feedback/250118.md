# 给 250118（yaku.py）的反馈

役种覆盖很广，役满与不同拆分都有考虑。原文件最大的问题不是少写了役，而是**返回信息不够、外层只能猜番数**。本轮修复如下：

1. 新增 `calc_yaku_detailed`，逐项返回 `{name, han}`；原 `calc_yaku` 仍返回名字列表和总番，兼容已有调用。前端不再用不完整名称表猜番。
2. `kuitan=false` 时副露断幺不再算役；`aka_dora=false` 时红五不额外计番。规则由 game 传入。
3. 表宝、`state['ura_dora']` 里宝、赤宝分别计番和显示；无役时宝牌不能单独让牌可和。
4. 同时接受 `chihou` 与旧拼写 `chiihou`，修复 game 的状态键对不上导致地和丢失。
5. 修复递归拆牌对剩余牌数不一致、负数计数等非法输入可能抛异常的问题，改为正常返回无役。
6. 特殊牌型与普通拆分统一比较总番，避免候选结果被直接覆盖。
7. 详细役满使用 13/26 番表示单/双倍，复合可累加；暗杠下标由上层传入。

`test_yaku.py` 的 10 项测试已通过，另做了 5000 组随机输入崩溃检查。以后新增役请同时返回自身番数，并补“门清/副露、是否自摸、和牌位置”的测试，别让 server 再维护第二份役表。

## 第二轮反馈

**抢杠本身就是一番状况役，不能要求门清，也不能只作为其他役的附属。** 当前 `situation_yaku` 在非自摸且 `state['chankan']` 时直接加入 `('抢杠', 1)`，随后即使没有其他役也能形成 `best_yaku`。本轮新增“和牌者带一个明刻、除抢杠外无役”的回归测试，和原门清测试都通过。保持这个结构即可；不要把它写成 `if closed and ...`，也不要等 game 先判断“已有其他役”后才调用你。

### 番与符使用同一拆法

新增 `calc_hand_details`，在枚举每种一般形/七对子/役满候选时就把该形状交给算符，并按“不含宝牌的番数、同拆法的符数”选择候选，最后返回 `(详细役, 总番, 符)`。宝牌仍在选定牌型后追加，不参与无役判断。`calc_yaku` 和 `calc_yaku_detailed` 保持原返回格式。

这样平和不会拿另一种单骑解释的符，一杯口＋混全也不会拿三个刻子解释的高符。以后新增候选役时必须走 `consider(..., shape)`，不要只更新番而漏掉对应 shape。
