## 3. 一杯口 + 混全的牌荣和，点数高了一档（要你配合改）

- **现象和原因**：跟 260331 那条是同一件事，详细的例子见他的反馈。111222333m 789p 北北荣和 3m：你按“123m ×3”给了一杯口 + 混全 3 番，这是对的；但 fu.py 按“111m 222m 333m”给了 50 符，两种拆法凑在一起，算成了 6400（应该是 5200）。

  你的 `calc_yaku` 只返回番最多的那一种（yaku.py:397-405），game.py 不知道这个番是哪种拆法算出来的，也就没法跟符对上。
- **怎么改**：
  1. 新加 `calc_yaku_candidates(...)`，参数跟 `calc_yaku` 一样，返回 `(役满列表, 役满倍数, [(拆法, 役列表), ...], 宝牌列表)`。不是役满的时候，把每种拆法、每个和牌位置的役都列出来，不含宝牌。宝牌跟拆法无关，单独给一次。
  2. 拆法的写法跟 260331 约定成一样的：`(雀头, 手里的面子排好序的元组, 和牌落在哪)`。你的 `'triplet'` 写成 `'ke'`，`'sequence'` 写成 `'shun'`；和牌位置 `('pair', None)` 写成 `('pair', 雀头)`；七对子写 `'chiitoitsu'`。
  3. 你在 yaku.py:386-405 的循环里本来就是一种拆法一种拆法算的，每次 `candidates.append((key, yaku))` 就行，不用当场挑最大的：

     ```python
     KIND = {"triplet": "ke", "sequence": "shun", "pair": "pair"}
     key = (pair,
            tuple(sorted((KIND[kind], tile) for kind, tile, _ in hand_groups)),
            (KIND[wait[0]], pair if wait[0] == "pair" else wait[1]))
     candidates.append((key, yaku))
     ```

  4. 原来的 `calc_yaku` / `calc_yaku_detail` 留着，改成从候选里挑番最多的，以前的调用不受影响。
- **修改版**：yaku.py 的 `calc_yaku_candidates`、`calc_yaku_detail`，标了 `[第二轮]`。

## 1. 加杠时别人听那张，不能抢杠

这条是 game.py 那边没做（见 250207 的反馈）。你在 `situation_yaku` 里早就写好了“抢杠”（yaku.py:253-254），game.py 把 `state['chankan']` 传对就能算出来，你这边不用改。

## 建议

函数只返回“最好的那一个”用起来很方便，但调用的人有时候需要拿到所有候选，跟别的信息一起比。设计接口的时候可以多想一步：调用我的人还需要知道什么？
