## 2. 摸到一样的牌，新摸的那张跑到手牌最右边

- **现象**：手里有一张 2m，又摸到一张 2m，手牌显示成 1m 3m … 4p 2m，后面再跟着摸的那张 2m，顺序乱了。
- **原因**：game.py 的手牌里包含刚摸的牌，而且放在最后（game.py:212 的 `self.hands[seat].append(t)`）。前端要手牌和 `drawn` 分开，server 拆的时候用了 `hand.remove(drawn)`（server_patch.py:181）。`remove` 删掉的是**第一张**一样的牌，也就是排好序的那张，留下的反而是放在最后的新牌。
- **怎么改**：删最后那张：

  ```python
  for i in range(len(hand) - 1, -1, -1):
      if hand[i] == g.drawn:
          del hand[i]
          break
  ```

  你原来的 server.py 直接把含摸牌的手牌给了前端，同时又给了 `drawn`，前端会把摸的牌画两遍，所以也要这样拆。
- **修改版**：server.py 的 `build_state`。

## 10. 真人不在座位 0 时，开局返回的视角不对

- **现象**：`players` 传 `['bot', 'human', 'bot', 'bot']` 开局，返回的是座位 1 的视角。
- **原因**：前端说明的接口一览写着 `new_game` 返回“座位 0 的视角”（接口说明.md:54）。老师的补丁返回的是第一个真人座位（server_patch.py:276、280），修改版沿用了。你原来的 server.py 默认返回座位 0（server.py:186、190），是对的。
- **怎么改**：`new_game` 一律返回座位 0 的视角；要别的座位的视角，就调 `GET /api/state?game_id=…&seat=n`。
- **修改版**：server.py 的 `api_new_game`。

## 建议

做格式转换时，可以对着说明每个字段写一个小测试，比如“返回的 viewer 等于 0”“hand 是排好序的”。这比靠页面顶上的红字检查更全：红字只能查出字段缺没缺、类型对不对，查不出值对不对。
