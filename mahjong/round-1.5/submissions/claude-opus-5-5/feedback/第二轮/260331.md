## 3. 一杯口 + 混全的牌荣和，点数高了一档

- **现象**：111222333m 789p 北北，东场南家荣和 3m。大家手算是一杯口 + 混全 3 番 40 符，5200 点；程序给了 3 番 50 符，6400 点。
- **原因**：就是你在 fu.py:43-44 的 TODO 里写过的那件事。这手牌有两种拆法：
  - 123m 123m 123m 789p：一杯口 + 混全。符是 20 + 10（门前荣和）+ 2（边张，12 听 3）= 32，进位成 40 符。
  - 111m 222m 333m 789p：三个刻子。符是 20 + 10 + 8 + 4 + 2（荣和补成的 333m 算明刻）= 44，进位成 50 符。可这种拆法一个役都没有。

  `calc_fu` 取所有拆法里符最大的（fu.py:357-358），得到 50；250118 取番最多的，得到一杯口 + 混全 3 番。两个最大值来自不同的拆法，凑在一起就多算了。第一轮加的 `is_pinfu` 只补了“平和”这一种情况，这次是“刻子还是顺子”两种拆法，所以没挡住。
- **怎么改**：不要只返回一个最大值，而是每种拆法各返回一个符数，让 game.py 按拆法把符和番对上：
  1. 新加 `calc_fu_table(...)`，参数跟 `calc_fu` 一样，返回 `{拆法: 符数}`。
  2. 拆法的写法跟 250118 约定成一样的：`(雀头, 手里的面子排好序的元组, 和牌落在哪)`。面子就用你现在的 `('ke', '5m')` / `('shun', '3m')`；和牌落在哪写 `('pair', 雀头)` / `('ke', 牌)` / `('shun', 顺子最小那张)`；七对子写 `'chiitoitsu'`，国士写 `'kokushi'`。
  3. 你现在的循环（fu.py:290-358）已经把每种拆法、每个和牌位置都算过一遍了，只要把最后的“取最大”改成“记进字典”：

     ```python
     if wei_zhi == -1:
         he_pai_wei_zhi = ('pair', que_tou)
     else:
         he_pai_wei_zhi = tuple(mian_zi_men[wei_zhi])
     key = (que_tou, tuple(sorted(tuple(m) for m in mian_zi_men)), he_pai_wei_zhi)
     table[key] = max(table.get(key, 0), fu_shu)
     ```

  4. 原来的 `calc_fu` 留着，改成从这张表里取最大值，别人以前的调用不受影响。
  5. 七对子也放进表里，即使这手牌也能拆成一般形（比如二杯口）。两种都列出来，让 game.py 按点数挑。
- **修改版**：fu.py 的 `calc_fu_table` 和 `_fu_table`，标了 `[第二轮]`。
