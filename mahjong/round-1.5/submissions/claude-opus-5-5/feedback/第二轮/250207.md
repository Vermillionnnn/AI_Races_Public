## 1. 加杠时别人正好听那张，不让和（抢杠）

- **原因**：抢杠还没做。`_kakan`（game.py:606-617）直接把碰改成杠；`_make_state` 里 `'chankan'` 写死成 False（game.py:314）。
- **怎么改**：把加杠拆成两步：
  1. `_kakan` 里先不改副露，记下 `self.chankan_pending = (seat, 牌种, 那张牌)`，再对另外三家调 `_can_ron(s, 那张牌)`。
  2. 有人能和：`call_options` 里只放 `{'type': 'ron'}`，`phase = 'call'`，跟打牌后等别人鸣牌一样等大家回应。没人能和就直接做第 3 步。
  3. `_resolve_calls` 开头先看 `chankan_pending`。有人荣和，就按荣和结算（放铳的是加杠的人）；都跳过，就真的完成加杠：改副露、翻杠宝牌、摸岭上牌。
  4. `_make_state` 里写 `'chankan': (not is_tsumo) and self.chankan_pending is not None`。250118 的 yaku.py 早就会算“抢杠” 1 番（yaku.py:253-254），传对就行。
  5. `_interrupt()`（清一发）挪到加杠真正成立以后再调。被抢杠的时候，抢的人的一发还在。
  6. 能抢没抢的人，跟平常一样算同巡振听。`_resolve_calls` 里现成的那段可以直接用。
- **修改版**：`_kakan`、新函数 `_finish_kakan`、`_resolve_calls` 开头、`_make_state`。
- 暗杠一般只有国士无双能抢，这个没做，规则文档里写了。

## 3. 一杯口 + 混全荣和，点数高一档（要你配合 260331、250118 改）

- **现象**：111222333m 789p 北北，荣和 3m。正确是一杯口 + 混全 3 番 40 符，5200 点；程序给了 3 番 50 符，6400 点。
- **原因**：番和符来自两种不同的拆法。算番按“123m ×3”（一杯口 + 混全），算符按“111m 222m 333m”（三个刻子 50 符，可这种拆法一个役都没有）。`_score_one` 分别调了两个函数（game.py:640-643），两边各取各的最大值。
- **怎么改**：260331、250118 各加一个“每种拆法分别给结果”的函数，拆法写法统一（见他们的反馈）。你在 `_score_one` 里按拆法把番和符对上，每种拆法算一次点数，取最高的：

  ```python
  ym_pairs, yakuman, cands, dora_pairs = calc_yaku_candidates(...)   # 250118
  fu_table = calc_fu_table(...)                                       # 260331
  best = None
  for key, yaku in cands:
      if not yaku or key not in fu_table:
          continue
      han = sum(h for _, h in yaku + dora_pairs)
      fu = fu_table[key]
      pts = calc_score(fu, han, is_oya, is_tsumo, 0, 0)['get']
      if best is None or (pts, han, fu) > best[0]:
          best = ((pts, han, fu), yaku + dora_pairs, fu)
  ```

  役满时不用挑，直接用役满的结果。
- **修改版**：`_score_one`。

## 4. 吃完手里只剩食替不能打的牌

- **现象**：副露多了以后，比如手里只剩 3m4m5m6m，用 4m5m 吃 3m，剩下的 3m、6m 都是食替不能打的。
- **原因**：出吃碰选项的时候（game.py:248-256）没看食替。吃完以后 `_turn_actions` 发现一张都不能打，又退回成“哪张都能打”（game.py:352 的 `or discards`），结果等于被迫违反食替。我们没有复现出程序卡死，但这一步确实不对，正确的做法是一开始就不给这种吃法。
- **怎么改**：生成每个吃、碰选项时先模拟一下：从手里拿掉这两张，剩下的牌里至少要有一张不在食替列表里，否则不给这个选项。食替列表你已经在 `_call_meld` 里算过了（game.py:587-595），把那段抽成函数，两处共用：

  ```python
  def _kuikae_ok(self, seat, own, tile, kind):
      rest = list(self.hands[seat])
      for t in own:
          rest.remove(t)
      bad = self._kuikae_tiles(tile, own, kind)   # 就是 _call_meld 里算食替的那段
      return any(norm(t) not in bad for t in rest)
  ```

- **修改版**：`_kuikae_tiles`、`_kuikae_ok`，`_discard` 里生成选项的地方。

## 5. 立直宣言牌被和了，结算上还挂着立直

- **原因**：一宣言就 `self.riichi[seat] = True`（game.py:227）。宣言牌被荣和时立直不成立，但代码没有撤回（game.py:521-523）。点数是对的（立直棒本来就没交），只是显示错了。
- **怎么改**：`_resolve_calls` 里有人荣和时（包括三家和），如果 `self.riichi_pending == discarder`，就把这个人的 `riichi`、`double_riichi`、`ippatsu` 都改回 False，再把 `riichi_pending` 设成 None。
- **修改版**：`_resolve_calls`。

## 6. 两人合计开了四个杠，第四个杠的人打的牌还能被碰

- **原因**：四杠散了在你原来的版本里还是 TODO（game.py:560）。我在修改版里第一轮补的时候，只做了“这张牌没人和就流局”，漏了“这张牌不能鸣”，所以这张被碰了就不流局了。这条是我补漏了，不是你写错的。
- **怎么改**：写一个函数判断“两人以上合计开了 4 个杠”，条件是 `len(self.kan_seats) >= 4 and len(set(self.kan_seats)) > 1`。打牌后生成选项时，满足这个条件就只给荣和、不给吃碰杠，跟河底那张一样处理；`_after_discard_pass` 里没人和就流局。一个人自己开 4 个杠是四杠子的机会，不流局。
- **修改版**：`_four_kan_abort_pending`、`_discard`、`_after_discard_pass`。

## 7. 最后一局庄家和了，跟起家同分就直接结束了

- **原因**：和了止め判断“庄家是不是第一”用的是 `self.scores[self.oya] == top`（game.py:747），同分也算庄家第一。按大家的规则，同分时起家顺序在前（座位号小）的人排前面。
- **怎么改**：

  ```python
  ranking = sorted(range(4), key=lambda s: (-self.scores[s], s))   # 分高的在前，同分座位号小的在前
  if is_win and ranking[0] == self.oya and self.scores[self.oya] >= RETURN_POINTS:
      return True
  ```

  你在终局排名那里（game.py:732）已经是这么排的，这里用同一个规则就行。
- **修改版**：`_check_game_over`。

## 8. 终局剩下的立直棒加给了第一名，结算的点数变化里却没有

- **原因**：game.py:727-728 只加到了 `self.scores`，没有加到 `delta`。
- **怎么改**：同时写 `delta[top] += self.kyotaku * 1000`。`result['delta']` 和 `delta` 是同一个 list，改一个就行。这样四家的点数变化加起来正好等于拿走的立直棒，前端说明也是这么要求的。
- **修改版**：`_end_round`。

## 建议

这 7 条里有 4 条（第 4、6、7、8 条）都是同一类问题：同一件事出现在两个地方，只改了一处。食替在出选项和打牌时用的规则不一样；“谁是第一”在两个地方算法不一样；点数加到了 `scores`，没加到 `delta`。以后写到同一件事要在两处用时，抽成一个函数或一个变量，就不容易漏。
