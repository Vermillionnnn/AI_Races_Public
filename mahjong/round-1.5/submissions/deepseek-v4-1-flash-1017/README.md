## 启动

在**本目录**执行：

```bash
python3 server.py --port 8000
```

然后打开 <http://127.0.0.1:8000/>。

- `--port` 可省略，默认 `8000`；不带参数时监听 `127.0.0.1:8000`。
- `GET /` 返回 `frontend/index.html`。
- 接口前缀 `/api/...`，格式见 `frontend/接口说明.md`。
- 开发时也可以用 `python3 server.py --port 8765`，页面地址相应改端口。

Windows 下把 `python3` 换成 `py -3.13` 即可：

```powershell
py -3.13 server.py --port 8000
```

## 主要修复

### 会直接让牌局不对的

1. **牌山顺序**：配牌改为按物理座位 `wall[0:13]/[13:26]/[26:39]/[39:52]`；庄家第一摸 `wall[52]`；王牌改为 `[122:127]` 宝牌指示牌、`[127:132]` 里宝牌、`[132:136]` 岭上牌。
2. **算点接口**：`game.py` 同时接受 `score.py` 的 dict 和旧的元组；不再依赖 `server.py` 的 monkeypatch。
3. **暗杠**：`game.py` 把 `an_gang` 和 `ankan_indices` 传给符/番模块，暗杠不再被当成明杠，也不破门清。
4. **里宝牌**：普通宝牌和里宝牌分开传，结算里分别显示“宝牌/赤宝牌/里宝牌”。
5. **规则开关**：`aka_dora`、`kuitan`、`kiriage_mangan`、`renpu_fu` 从 `new_game.rules` 一路传到算番/算符/算点；页面新增四个选择控件。
6. **东风/半庄**：`length` 真正生效；东风战东 4 结束，半庄战南 4 结束，庄家连庄会延长。

### 接口和体验

7. **`server.py` 按前端说明重写**：`--port`、`GET /`、`game_id`、`version`、`viewer`、`turn`、`waiting_for`、`rules`、`players` 字段名、`hand`/`drawn` 分离、`legal_actions` 的 `options`、`hints` 的 `{tile,left}`、`result` 的 `agari/ryuukyoku`、`events` 事件流。
8. **多人同时鸣牌**：`waiting_for` 只列还没回复的人类座位，收齐后按 和 > 碰/杠 > 吃 处理。
9. **振听**：同巡振听改为下一次自己摸牌时清除；立直宣言牌被荣和时撤销立直。
10. **小问题**：碰的红五选项、暗杠 `from:null`、`called_tile`、摸切标记、`tsumogiri`、食替、双响/三家和/四杠散了等。

### 第二轮补充修复

11. **符和番用同一种拆法**：`yaku.py` 把选中的拆法写进 `state['_decomp']`，`fu.py` 按这个拆法算符；修掉平和多 10 符、一杯口+混全点数高估的问题。
12. **抢杠**：加杠前先询问其他家能否荣和；被抢杠时加杠不成立、不翻杠宝牌，结算有“抢杠”1 番。
13. **四杠散了**：改成“总共四个杠且不是同一个人开的”才流局；一个人四杠是四杠子，不流局。
14. **手牌排序**：`server.py` 从手牌末尾移除刚摸的牌再排序，避免摸到同种牌时手牌乱序。
15. **剩余张数**：被鸣走的牌不再从牌河重复扣；别人的暗杠不当作“看得到”；打牌提示把即将打出的牌也算进已见牌。
16. **食替卡住**：吃/碰前先检查鸣牌后是否还有合法舍牌，没有就不提供这个鸣牌选项。
17. **终局立直棒**：最后一局结束给第一名的立直棒也计入该局 `result.delta`。
18. **全电脑开局**：`human_seats` 为空时不再兜底成座位 0，全电脑会自己跑完一局。

## 测试

本目录下没有放测试脚本（避免污染部署目录），实际跑过的检查包括：

- `py_compile` 全部模块通过。
- 东风/半庄 × 有无红五/食断/切上/连风组合 × 多个种子，全电脑对局跑到终局；每局 `sum(scores) + kyotaku*1000 == 100000`，终局 `sum(scores) == 100000`。
- 人类座位 0 随机合法操作，跑到终局，点数守恒。
- 指定牌山：四家配牌、庄家第一摸、宝牌指示牌、`wall_left=69`。
- 暗杠：`wall_left` 减 1、岭上牌来自 `wall[132]`、宝牌指示牌翻到 `wall[123]`。
- 规则开关：无红五牌山、食断 0/1 番、连风 2/4 符、切上 7700/8000。
- 符：平和自摸 20、平和荣和 30、七对子 25、暗杠自摸 60/明杠 40。
- 符番拆法一致：平和荣和/自摸分别 30/20；一杯口+混全按选中拆法算符（不再取另一种高符拆法）。
- 番：三色、一气、混一色、清一色、对对、三暗刻、小三元、九莲、字一色、绿一色、清老头、大四喜等。
- 抢杠：加杠时能荣和、`result.wins[].yaku` 有“抢杠”、被抢后加杠不成立且不翻杠宝牌。
- 四杠散了：两人各两杠流局；一人四杠不流局。
- 终局立直棒：`result.delta` 包含给第一名的立直棒，且四项和与分数变化一致。
- 全部电脑：`players=['bot']*4` 的 `new_game` 直接跑完一局，`waiting_for=[]`。
- 手牌排序：摸到与手牌相同的牌时，`hand` 仍按牌种排序，`drawn` 单独给出。
- HTTP：`GET /` 200；`new_game` 字段齐全；非法操作 400；`/api/state` 换视角；单人+电脑打完整场；四个 human 轮转打完整场；`/api/next` 进下一局；终局 `phase=game_end`。

## 已知边界

- 杠宝牌目前杠完立即翻；标准规则里明杠/加杠是打牌后翻。
- 没有包牌（PAO）、流局满贯、人和、十三不搭。
- 电脑玩家仍是最简单的“摸什么打什么、不吃不碰、能和就和”；全电脑对局经常荒牌是策略导致的，不是流程 bug。
- 三家和、四杠散了按途中流局处理，不做三家分别结算。
