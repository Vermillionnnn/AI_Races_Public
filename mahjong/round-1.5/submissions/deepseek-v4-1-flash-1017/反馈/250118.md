# 给 250118 的反馈（yaku.py）

役种覆盖得很全，一般形拆解、役满、宝牌/赤宝牌/里宝牌都考虑到了，`calc_yaku` 的“取番数最高的拆法”思路也对。主要问题是**状态字段名不统一**、**没有规则开关**、以及**只返回役名和总番数，前端拿不到每个役的番数**。

## 严重问题

1. **地和永远算不出来：`chiihou` vs `chihou`**
   - `game.py` 传给 state 的键是 `chihou`（你文件开头也写了“state 里我多加了一个 chihou”）。
   - 但 `tile_yakuman` 里判断的是 `state.get("chiihou")`，所以地和永远不成立。
   - 我改成 `state.get("chihou") or state.get("chiihou")`，两边都兼容。

2. **返回格式不够前端用**
   - 任务书约定返回 `(['立直', '平和'], 2)`，你按约定返回了“役名列表 + 总番数”。
   - 但前端结算要每个役的 `{name, han}`，而且 `han` 之和必须等于总番数；`server_patch.py` 之前用一张 `YAKU_HAN` 表估算，副露混一色、清一色、三色、一气这些会估错，役满也会被当成普通番。
   - 我加了可选参数 `detail=True`：默认仍然返回原来的 `(役名列表, 总番数)`，`game.py` 调用时返回 `([(役名, 番数), ...], 总番数)`，这样前端能直接显示，且和总番数严格一致。

3. **食断开关没有接**
   - `tile_yaku` 里断幺九无条件成立；副露后断幺九也照算。
   - 已加 `rules` 参数：`closed` 或 `rules['kuitan']` 为真才算断幺九。

4. **赤宝牌开关没有接**
   - `dora_yaku` 里 `red = sum(tile in RED_FIVES ...)` 无条件数红五。
   - 规则 `aka_dora=false` 时牌山本来就不该有红五，但测试牌山或旧局可能带；已加 `rules['aka_dora']` 判断。

## 中等问题

5. **里宝牌从来没拿到**
   - 你写了 `state.get("ura_dora")`，但 `game.py` 只传了 `dora`，没传 `ura_dora`；它把里宝牌也塞进了 `dora`。
   - 结果：里宝牌被标成“宝牌”，不是“里宝牌”；而且如果 `dora` 里同时有普通宝牌和里宝牌，无法区分。
   - 已让 `game.py` 传 `state['ura_dora']`，`dora` 只放普通宝牌。

6. **暗杠信息没有传进来**
   - `read_melds(melds, state.get('ankan_indices', []))` 写对了，但 game 没传 `ankan_indices`，所有杠都被当成明杠。
   - 影响：`closed` 变 false，门前清自摸、立直、平和、一杯口、二杯口都可能丢；暗杠的 `四暗刻` 也会算错。
   - 已由 game 传 `ankan_indices`。

7. **`yaku_kokushi` 的 `counts.keys() == ORPHANS`**
   - 在 CPython 里 `dict_keys` 和 set 比较通常能工作，但这属于依赖实现细节；已改成 `set(counts.keys()) == ORPHANS`，更稳。

8. **累计役满和真正役满的区分**
   - 你按约定把役满返回 13 的倍数（双倍 26），这点没问题。
   - 但前端要求：真正役满 `yakuman` 写倍数；累计役满（普通役加起来 ≥13 番）`yakuman` 写 0。仅凭役名列表无法区分，所以我在 `yaku.py` 里加了 `YAKUMAN_NAMES` 和 `is_yakuman_names(names)`，由 game/server 判断。你以后加役满役种时，记得同步这个集合。

## 小建议

9. `yaku_pinfu` 的听牌形判断我复核过：123 和 1、789 和 9 是两面；123 和 3、789 和 7 是边张；中间是嵌张。当前逻辑是对的。
10. `yaku_chanta`/`yaku_junchan` 用 `sequences` 是否为空来排除“对对和型”，这个写法可以；但 `混老头` 和 `混一色` 可能复合，结算时按番数取最大拆法即可。
11. `yaku_sanshoku_doujun`、`yaku_ittsuu`、`yaku_sanshoku_doukou` 都用了 `starts` 集合，和牌拆法不同会导致结果不同；你现在按每种拆法都算一遍再取最大，方向是对的。
12. `yaku_chuuren` 用 `counts[win_tile] > base[win_tile]` 判断纯正九莲，前提是 `win_tile` 在 base 里；同一花色 1–9 都在 base 里，所以没问题。
13. `tile_yakuman` 的天和判断用 `jikaze == "1z"`，庄家的自风一定是东，没问题；地和用 `jikaze != "1z"` 也正确。

## 我改完后你最好自己再看一眼

- `calc_yaku` 新参数是 `(..., rules=None, detail=False)`，前 8 个参数没动。
- `detail=True` 时返回的每个役番数之和等于总番数；役满每个役写 `13 × 倍数`，和接口说明一致。
- `YAKUMAN_NAMES` 里包含“国士无双十三面”“纯正九莲宝灯”“四暗刻单骑”“大四喜”等双倍役满名字，新增役满时别忘了加。
