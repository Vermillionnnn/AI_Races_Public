# 给 250226 的反馈（server.py）

你把游戏逻辑、算符、算番、算点、听牌几个模块接起来的思路是对的，也自己做了兼容层，能看出你在努力让大家不同的返回格式先跑起来。主要问题是**没有按前端接口说明输出**，以及**启动方式不对**；这两条会直接导致页面顶上红字、服务器起不来。

## 严重问题

1. **启动命令和端口不对**
   - 说明要求：在项目根目录执行 `python3 server.py --port 8000`，不带参数默认 8000，只监听 `127.0.0.1`。
   - 你的 `server.py` 只读环境变量 `PORT`，默认 5000，而且没有 `--port` 参数；服务器按说明启动会直接失败。
   - 已改成 `argparse` 的 `--port`（默认 8000），并用 `ThreadingHTTPServer`。

2. **`GET /` 没有返回页面**
   - 说明要求 `GET /` 返回 `frontend/index.html`（HTTP 200），服务器最多等 30 秒。
   - 你返回的是 `{"ok": true, "msg": "mahjong backend running"}`，页面打不开。
   - 已让 `/` 和 `/index.html` 返回 `frontend/index.html`。原来的 `server_patch.py` 做了这件事，但那是老师的补丁，不应该作为最终入口；现在正式 `server.py` 自己就能提供页面。

3. **状态字段和接口说明对不上**
   - 你的 `_build_state_response` 输出的是 `ok/seat/round/dora/remaining/current/...`，前端要的是：
     - 顶层：`version`、`game_id`、`phase`、`round`、`dora_indicators`、`wall_left`、`viewer`、`turn`、`waiting_for`、`rules`、`players`、`drawn`、`legal_actions`、`hints`、`events`、`result`。
     - 玩家：`seat_wind`（不是 `wind`）、`discards`（不是 `river`）、`hand_count`、`hand` 只给 viewer、`melds` 带 `type/tiles/from/called_tile`。
     - `phase` 是 `playing/round_end/game_end`，不是 `discard/call/end`。
   - 前端格式检查会把这些全部报出来。已按说明重写适配层。

4. **`new_game` 忽略 `players/length/rules`**
   - 你只取了 `seat`、`wall`、`seed`，`human_seats=[seat]`；页面传的 `players`（四个 human/bot）、`length`（东风/半庄）、`rules`（四个开关）全丢了。
   - 已解析 `players` 得到 human 座位、把 `length` 和 `rules` 传给 `game.Game`；`new_game` 返回座位 0 视角，`game_id` 每次新生成。

5. **操作类型没有转换**
   - 前端发 `ankan/kakan/minkan`，`game.py` 统一叫 `kan`；前端发 `tsumogiri`，你完全没接；前端发 `chi/pon` 带 `tiles`，你只传了 `tile`。
   - 已做映射：`ankan/kakan/minkan -> kan`，`chi/pon` 传 `tiles`，`discard/riichi` 传 `tile` 和 `tsumogiri`，`pass/kyuushu/tsumo/ron` 原样。

## 中等问题

6. **`game_id` 没有实现**
   - 说明要求每次 `new_game` 给新 `game_id`，旧局可以不留；你的 `server_patch.py` 固定 `g1`，`server.py` 干脆没有 `game_id`。
   - 已用全局计数器生成 `g1/g2/...`，`/api/state`、`/api/action`、`/api/next` 都按 `game_id` 找局；只保留最近 4 局。

7. **听牌提示格式不对**
   - `game._build_hints` 返回 `{waits: {牌: 张数}, discards: {牌: {牌: 张数}}}`，前端要 `{waits: [{tile, left}], furiten, discards: {牌: [{tile, left}]}}`。
   - `server_patch._hints` 做了一部分，但没有 `rules`、`waiting_for`、`events`。已在正式 server 里统一转换，并给 `furiten` 用 `game._is_furiten`。
   - 注意 14 张时 `_is_furiten` 不能直接拿 14 张判断；现在只在 13 张 `waits` 时给 `furiten`，14 张 `discards` 时 false。

8. **结算格式不对**
   - 前端要 `result.type = 'agari'`、`wins[]`、`dora_indicators`、`uradora_indicators`、`delta`。
   - 你的 `game.result` 是 `type='tsumo'/'ron'`，里宝牌叫 `ura_indicators`，`wins[].yaku` 是役名列表；`server_patch` 又用 `YAKU_HAN` 估每个役的番，副露混一色/清一色/三色/一气/役满都会估错。
   - 已让 `yaku.calc_yaku(detail=True)` 直接返回每个役的番数，server 原样输出；`yakuman` 用 `is_yakuman_names` 判断，累计役满写 0；`points` 用 `score.py` 新增的不含本场/供托的值。

9. **`waiting_for` 和多人操作**
   - 前端要求：打牌后多人可鸣牌/荣和时，`waiting_for` 列出还没回复的人类座位；收齐后再按 和 > 碰/杠 > 吃 处理。
   - `game.py` 本身支持 `responses`，但你的 server 没有把 `waiting_for` 暴露出来；已在 `build_state` 里按 `game.call_options` 和 `game.responses` 计算，并且只列人类座位。
   - 电脑玩家的操作由 `game._run` 自动跑完，server 不需要额外循环。

10. **事件流是空的**
    - 前端记录栏要 `events`（draw/discard/riichi/chi/pon/minkan/ankan/kakan/dora/tsumo/ron/ryuukyoku）。
    - 你之前 `events: []`。已在 `game.py` 里记录，server 对别人的摸牌 `tile` 置 null，避免泄露手牌。

## 小建议

11. 不要再用 monkeypatch 改 `game.calc_score` 来兼容 `score.py`；这次已经让 `game._parse_score` 同时接受 dict 和元组，server 不再需要兼容层。
12. 单进程多请求：`HTTPServer` 是单线程的，一个请求卡住会阻塞其他请求；已换 `ThreadingHTTPServer`，并用 `LOCK` 保护全局对局状态。
13. 出错时统一返回 `{"error": "..."}` + 4xx/5xx；前端会弹 `error`。已按这个格式处理非法座位、非法操作、牌山长度、规则值等。
14. `server_patch.py` 可以留作历史参考，但最终入口请用 `server.py`；我把提交里的 `server_patch.py` 去掉了，避免部署时启错文件。
