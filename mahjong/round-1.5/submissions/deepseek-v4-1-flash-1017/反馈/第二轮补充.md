## 250207（game.py）

### 1. 平和多 10 符、一杯口+混全点数高

不是 `fu.py` 单独算错了，是 `game.py` 让 `fu.py` 自己“取符数最大的拆法”，而 `yaku.py` 取的是“番数最高的拆法”。两种拆法可能不是同一种：

- 例：`345m 456s 345p 456p 11s` 和 `4p`，`yaku.py` 走 `456p` 的两面听算平和；
  `fu.py` 却可以走 `345p` 的嵌张听，多 2 符，再门前 +10，变成 40 符。
- 一杯口+混全也是同理：刻子拆法符高，顺子拆法番高，最后符和番对不上。

**改法**：`yaku.calc_yaku` 在更新 `best_yaku` 时把 `(pair, hand_groups, wait)` 记到 `state['_decomp']`；`game._score_one` 调 `calc_fu` 时把这个 `decomp` 传进去。`fu.py` 收到 `decomp` 就只按这一种拆法算，不再自己枚举取最大。

你那边要改的就是 `_score_one`：

```python
state = self._make_state(seat, is_tsumo)
yaku, han = calc_yaku(..., state, ..., detail=True)
fu = calc_fu(..., yaku_names=yaku_names, decomp=state.get('_decomp'))
```

### 2. 加杠没让人抢杠

`_kakan` 原来直接改副露、翻杠宝牌、摸岭上牌。正确顺序是：

1. 先从手里找到第四张 `x`；
2. 先问其他三家 `_can_ron(s, x, chankan=True)`；
3. 有人能和 → 进入 `phase='call'`，只给 `ron/pass`；有人荣和就 `_win_ron(..., chankan=True)`，加杠不成立、不翻杠宝牌；
4. 没人抢 → 再真正把手里的 `x` 并进碰，`_after_kan`。

`_make_state` 要把 `chankan` 传成 true，`yaku.situation_yaku` 已经有“抢杠”1 番。注意被抢时要把 `x` 从加杠者手里删掉（那张牌已经给和牌者了），但原来的碰要保持 3 张，不要变成加杠。

### 3. 两个人加起来四个杠没流局

原来的判断是 `len(set(kan_seats)) >= 4`，只有四家各一杠才流局；两个人 2+2 不会触发。

**改法**：

```python
if len(self.kan_seats) >= 4 and len(set(self.kan_seats)) > 1:
    self._abort('四杠散了')
```

一个人开四个杠是四杠子，不能流局；两个人或三个人凑到四个杠才流局。

### 4. 终局立直棒没进 delta

`_end_round` 里终局把 `kyotaku` 给第一名时，只改了 `self.scores`，没有改 `result['delta']`。要同时加：

```python
bonus = self.kyotaku * 1000
if bonus:
    self.scores[top] += bonus
    delta[top] += bonus
    result['delta'] = delta
self.kyotaku = 0
```

这样页面上的“变化”和“现在点数”能对上，`delta` 四项和也等于拿走的供托。

### 5. 食替卡住

`_turn_actions` 里“过滤后为空就退回全部”只是兜底，真正该做的是**在生成吃/碰选项时就检查**：这个鸣牌做完以后，手里还有没有不在食替集合里的牌。

新增 `_kuikae_set(kind, own, tile)` 和 `_can_discard_after_call(seat, kind, own, tile)`；`_discard` 生成 `chi/pon` 选项时过滤掉“做完没牌可打”的选项。这样玩家根本不会看到那个吃法。

### 6. 剩余张数被扣两次

`game.get_visible()` 原来把**所有牌河**（包括 `called=True` 的牌）和**所有人的副露**都放进去；`tenpai.get_waits` 又会加自己的副露。被鸣走的牌同时在“牌河”和“副露”里，就扣了两次。

**改法**：`get_visible` 里只放 `not r['called']` 的牌河；自己的副露完全不放（tenpai 会加）；别人的暗杠不要放（盖着的，不算看得到）。这样被鸣走的牌只从副露扣一次。

## 260331（fu.py）

### 平和/一杯口+混全的符和番对不上

`calc_fu` 原来的策略是“枚举所有拆法，取符数最大”。这个策略对单纯算符没错，但结算时 `yaku.py` 选的是番数最高的拆法，两者可能不是同一种。

**改法**：`calc_fu` 增加可选参数 `decomp`，格式是 `(雀头, 手牌面子, 和牌位置)`，由 `yaku.py` 选中后传进来。收到 `decomp` 就只算这一种拆法：

- 雀头 / 面子 / 和牌位置都按 `decomp` 来；
- 荣和补成的刻子算明刻，自摸算暗刻；
- 平和判断仍然按“门清 + 全顺子 + 雀头非役牌 + 两面”；
- 不再在 `calc_fu` 里自己取最大值。

`yaku_names` 里“七对子固定 25 符”的逻辑保留；`decomp` 传空时才走原来的枚举。

## 250118（yaku.py）

### 需要把“选中的拆法”暴露给 fu.py

这是这一轮符数/点数偏高的根因。`calc_yaku` 里维护 `best_yaku` 时，同时记录：

```python
best_decomp = None
...
if sum(n for _, n in yaku) > sum(n for _, n in best_yaku):
    best_yaku = yaku
    best_decomp = (pair, hand_groups, wait)
...
state['_decomp'] = best_decomp
```

注意不要把空 dict 参数重新赋值掉：

```python
if state is None:
    state = {}
# 不要写 state = state or {}，空 dict 会被替换成新对象，外面拿不到 _decomp
```

`game._score_one` 会把 `state['_decomp']` 传给 `fu.calc_fu`。抢杠那边 `situation_yaku` 已经有 `state['chankan']` 的 1 番，game 现在会在加杠被抢时把它设成 true。

## 260522（tenpai.py）

### 打牌提示的剩余张数偶尔多 1

`discard_hints` 里对每张要打的牌调用 `get_waits(rest, melds, visible)`，但没有把**这张即将打出的牌**加进 `visible`。打出去以后它会进自己的牌河，如果听的正好是这张，`left` 就会多 1。

**改法**：

```python
waits = get_waits(rest, melds, list(visible) + [tile])
```

其余不用改。注意 `visible` 的约定：**不含自己的副露**（`get_waits` 会从 `melds` 加），也**不含被鸣走的牌河**（那些已经在副露里）；别人的暗杠不算看得到。`game.get_visible` 已经按这个约定改了。

## 250226（server.py）

### 1. 手牌摸到同种牌时乱序

`game.hands[s]` 摸牌是 `append` 到末尾；`server` 原来用 `list.remove(drawn)` 删，删掉的是**手牌里较早的那张**，剩下的摸牌留在末尾，看起来就乱了。

**改法**：从末尾找第一张等于 `drawn` 的删：

```python
for i in range(len(hand_all) - 1, -1, -1):
    if hand_all[i] == g.drawn:
        del hand_all[i]
        break
hand_all.sort(key=game.tile_key)
```

### 2. 四个座位都设成电脑时开局卡住

`_new_game` 原来：

```python
seats = [i for i, p in enumerate(players) if p == 'human'] or [0]
```

全 bot 时兜底成 `[0]`，`game._run` 就停在“等座位 0 操作”。

**改法**：去掉 `or [0]`，全 bot 就是 `human_seats=[]`；`game._run` 会把这一局自动跑完，`waiting_for` 为空，不会再等谁。

### 3. 抢杠/终局 delta 不需要 server 额外改

抢杠仍然走 `phase='call'`，`waiting_for`、`legal_actions` 的 `ron/pass` 和普通荣和一样；`result.delta` 里已经包含终局立直棒，server 原样透传即可。
