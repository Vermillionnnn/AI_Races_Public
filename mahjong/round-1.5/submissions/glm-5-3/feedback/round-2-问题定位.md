# round-2 学生反馈：逐条定位（谁的问题、怎么改的、以后怎么防）

> 这轮大家的反馈质量很高，17 条里 15 条是真 bug（其中 1 条是我 round-1 自己改错的，详见第 4 条）。
> 所有修复都有回归测试：`tests/test_round2.py`，跑法 `py -3.13 tests/test_round2.py`。
> 按归属整理在最后。下面每条：**现象 → 原因 → 改法**。

## 逐条定位

### 1. 四番和了一万多点（四番四十符应该满贯封顶 8000）
- **归属：260409 score.py**
- 原因：`_get_limit_rank` 只按番数判满贯（`han >= 5`），漏了"**基本点超过 2000 也是满贯**"这条：4 番 40 符基本点 2560、3 番 70 符 2240，都该直接满贯。这些组合点数表里又没有，走了公式兜底，算出 10300/9000。
- 改法：`base = fu * 2 ** (han + 2)`，`base > 2000` 也判满贯（切上满贯还是走开关，管 1920 那档）。**以后防**：满贯线是"符×番过了 2000"，不是"番过 5"，写判定前把边界组合（4-40、3-60、3-70、2-110）列出来测一遍。

### 2. 双倍役满只给一倍的钱；13 番以上全显示成役满
- **归属：260409 + 拼装（server）**
- 原因 1：`LIMIT_TABLE` 根本没有二倍/三倍/四倍役满的档位，`han >= 26` 还是落进"役満"48000。
- 改法：表里加了 `'二倍役満' 96000/64000`、三倍 144000/96000、四倍 192000/128000，`_get_limit_rank` 按 26/39/52 分档。
- 原因 2：显示层用 `han // 13` 判断役满，把**累计役满**（普通役凑到 13+）也标成了役满。接口说明要求累计的 `yakuman` 写 0、照常显示符番，点数按役满。
- 改法（server.py）：看役名里有没有役满牌型（按表 13/26 番的）再决定 `yakuman` 标志。
- **以后防**：给结算写"役满显示/点数"的用例时，把"真役满、双倍、累计"三种都放进去。

### 3. 闲家第一张自摸没算地和
- **归属：250207 ↔ 250118 的接口约定**
- 原因：game.py 放进 state 的键叫 `chihou`，yaku.py 读的是 `chiihou`，一个字母之差，地和永远判不出来。这正是"多加参数没文档"的代价。
- 改法：yaku.py 两个键都认（`chiihou` 或 `chihou`）。
- **以后防**：跨模块的 state 键名写进分工文档；`天和/地和`的用例要进测试（round-1 的天和用例有、地和没有，漏网了）。

### 4. 两立直被别人碰掉变成普通立直
- **归属：我（round-1 拼装改错了，学生原版反而是对的）**
- 原因：round-1 我在 `_interrupt` 里把 `double_riichi` 也清了。规则上双立直只要求**宣言前**没人鸣牌，宣言之后的碰/吃只取消**一发**。
- 改法：撤掉那行，`_interrupt` 只清一发和 first_turn。
- **教训**：改规则相关代码前先拿具体牌例对着规则书核一遍，别凭"感觉更严格"就加判定。这轮的回归测试（碰过的双立直结算仍是两立直、一发没了）就是照这个场景写的。

### 5. 立直后摸到第四张还是不让暗杠
- **归属：我（round-1 的修法本身有 bug）**
- 原因：round-1 的 `_riichi_ankan_ok` 先把摸的牌从手里去掉、再去数四张杠牌——摸进第四张时手里只有三张，数不出四张，`len` 校验永远失败，恒返回"不能杠"。
- 改法：杠以前的听牌 = 打掉摸牌后的 13 张；杠以后手里是"原手牌 − 4 张杠牌"（10 张）+ 暗杠副露，听的牌 = 这 10 张再加一张就能和。两边比集合。回归测试：立直后摸第 4 张 1z → 暗杠 → 岭上摸到听的牌 → 岭上开花，全链路通。

### 6. 平和的符多了；一杯口/混全的牌高一档
- **归属：260331 fu.py 和 250118 yaku.py 的拆法不一致**
- 原因：符数在**所有拆法里取最大符**，番数在**番最大的拆法**上算——两边可能用的不是同一个拆法。能拆成平和的形（30 符）可能被另一种拆法算出 40 符，番还是平和那套，点数就高了一档。
- 改法（治标）：`calc_fu` 加了 `yaku` 参数，役里有**平和**时直接固定 20/30 符（game.py 已把役名传进去）。
- **还没做的**：完整的治本要"番×符一起枚举、取点数最高"（fu.py 的 TODO、你们文档里也提了），平和只是最常见的那个，下一轮 260331 和 250118 一起做。**手算对不上的时候先看看是不是这个**，另外别忘了门前符（+10）和听牌形符（嵌张/边张/单骑 +2）容易漏。

### 7. 副露的混一色、宝牌番数对不上
- **归属：没定位到 bug（按用例算是对的）**
- 用例：碰中 + 123m456m789m55m 和 5m、宝牌 5m：副露混一色 2 + 役牌中 1 + **一气通贯 1** + 宝牌 3 = 7 番，程序算的就是 7。容易手算错的两处：①**暗杠不破门清**，混一色还是 3 番、一气通贯还是 2 番；②宝牌要数**手牌+副露全部**（碰出去的红五也算）。下次对不上把整手牌（含副露、宝牌指示牌）发群里，我拿 `calc_yaku` 复算。

### 8. 只有抢杠一个役，不让和
- **归属：250207（state 传参）**
- 原因：加杠时给别人判断"能不能荣和"，用的 state 里 `chankan` 永远是 False——只有最后算分的 `_score_one` 才把它设 True。于是"只有抢杠一个役"的牌在**合法性检查**那一步就是 0 番，根本出不了和牌按钮。
- 改法：`_can_ron` / `_win_ok` 加 `chankan` 参数，加杠时传 True，让合法性检查和算分看到同一个 state。
- **以后防**："判断能不能"和"实际算分"要用同一套输入，这类双份逻辑最容易不同步。

### 9. 两个人开了四个杠没流局
- **归属：不是 bug（规则如此）**。四杠散了要求杠满 4 次的是**四家各一次**；一家/两家杠满 4 次不流局（不然四杠子这个役满就永远做不成了）。天凤、雀魂、M 联赛都是这么定的。程序行为正确；如果社团想改成"满 4 个杠就流"，改 `_after_kan` 里 `len(set(kan_seats)) == 4` 那行就行（去掉 set 去重），建议先讨论再动。

### 10. 红五+普通五只能碰一种拿法
- **归属：250207**
- 原因：原来只给一种（红五优先）。接口说明的 `pon` 本来就是多选项设计（`options`）。
- 改法：`_pon_options` 把手里能拿的两两组合都列成选项（`[5m,5m]` 和 `[5m,0m]`），前端会让你选。吃的多种组合 round-1 就是对的。

### 11. 食替那一下卡住 + 文档写得不对
- **归属：查了代码没发现卡死；文档是我的问题**
- 代码里"食替禁掉所有牌"时有兜底（全部放开），写了回归测试（副露满 4 组、手里剩两张全在食替名单里）也能正常打。**如果还能复现，把当时的截图或操作序列发我**——可能是前端渲染问题。
- 文档：`新手规则.md` 里"相邻的牌不能打"写得含糊，已改成精确说法：碰——刚碰的那种不能打；吃——刚吃的那张 + 手里能拼成同一副顺子的牌（4、5 吃 6 → 3 和 6；4、6 吃 5 → 只有 5）。

### 12. 立直宣言牌被荣和，结算还挂着立直
- **归属：250207**
- 原因：宣言牌被荣和时立直不成立、立直棒没放（这两个 round-1 就对了），但 `riichi` 标记没撤，结算界面还显示"立直"。
- 改法：`_win_ron` 里发现放铳的就是刚宣言的人时，把他的 `riichi / double_riichi / ippatsu` 一起清掉。

### 13. 最后一局庄家和了、和起家同分，直接结束
- **归属：250207（判定）**
- 原因：和了止め只看"庄家是不是最高分"，同分时直接算他第一。规则：**同分起家（座位 0）算上位**，庄家跟起家同分就不算第一，应该接着打。
- 改法：用 `(分数, 座位号小者优先)` 排名取第一，庄家必须是这个意义上的第一才结束。终局排名本来就是这套，两处对齐了。

### 14. 终局供托给第一名，但 delta 里没这一千
- **归属：250207**
- 原因：游戏结束把剩下的立直棒加进了 `scores`，但 `result['delta']` 没加，结算表"变化"和"现在"对不上。
- 改法：加进 scores 的同时也加进 delta（两边本来就是同一个 list）。

### 15. 手牌没排好、摸的牌跑到最右边
- **归属：接口行为 + 防御性排序**
- 摸的那张**单独**显示在最右边是接口说明定的（"我会把它和手牌隔开一点显示"），不是 bug。但后端确实应该把手牌排好序再发（说明里写了"顺序后端排好"），现在 server 里统一 `sorted()` 了，不会再出现乱序。

### 16. 听牌提示三个问题
- **归属：拼装（server）/ 260522（一个边界）**
- ①"碰过的那几张扣了两次"：`get_visible` 已经包含自己的副露，提示又把手里的 `melds` 传了一遍，等于扣两次。改法：把自己副露的牌从 visible 里去掉再传（吃 4m5m6m、听第 4 张 4m 的场合：剩 2 张而不是 1 张）。
- ②"打牌前的提示偶尔多一张"：`discard_hints` 数"还剩几张"时，**刚要打出去的那张**没算进看得到的牌——打的就是听的那张时会多一张。改法：tenpai.py 里把要打的牌加进 visible。
- ③"立直以后还提示别的牌"：立直只能摸切，再提示"打哪张能听"全是误导。改法：立直时只给"现在听什么"。

### 17. 前端朋友报的五处
- ①河里摸切/手切：**数据一直在**（game 记录、server 传递、前端有 `tsumogiri` 样式类），测试验证过电脑的河里标记是 True。看不出来应该是样式太淡（`filter: brightness(0.88)`），朋友可以把样式改明显点，后端不用动。
- ②副露的"从谁那儿鸣的、鸣的哪张"：**真 bug，两处**——game 的 `get_state` 没把 `called_tile` 传出来（一直在传 `from`）；大明杠的 meld 里压根没记 `called_tile`。都补上了，前端横着画的那张现在能对上。
- ③事件记录看到别人摸的牌：**真 bug**——`draw` 事件把所有人的牌都发下去了。接口说明要求只有摸牌人自己是 viewer 时才给 tile，现在按视角过滤。
- ④四个座位都电脑卡死：**真 bug**——`new_game` 里"没有人类就兜底当座位 0 是人类"，游戏干等一个不存在的人操作。现在人类列表直接传空，全电脑开局自动打完。
- ⑤真人不在座位 0 视角不对：**真 bug**——`new_game` 返回的是"第一个人类座位"的视角，接口说明规定**一律座位 0**。已改。
