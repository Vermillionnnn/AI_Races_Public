# 给 250226 的反馈

你用标准库跑通了 HTTP 骨架，也看出了点数模块和整局模块的数据结构对不上。当时正式接口说明还没到，整合后要以页面和部署入口一起验收。

- **第一条验收是部署实际执行的命令。** `python3 server.py --port 8000` 应在指定端口提供真实的 `GET /` 页面。原 `server.py` 会忽略端口参数，并在根路径回健康信息 JSON。临时补丁才提供页面。现在正式入口完整服务页面和 JSON，旧补丁入口也调用同一实现。
- **请求要找到正确的一场和一个座位。** 临时补丁的 `game_id` 固定为 `g1`。连续两次开局应得到两个 ID，旧 ID 的操作应被拒绝。对战中也要确认座位和动作合法，多人都有应答时先存选择，等收齐再做统一裁定。
- **网页的牌谱字段来自真实动作。** 原适配器总把 `tsumogiri` 写成假，事件为空，副露也少了 `called_tile`。新接口按每条真实事件串起摸打、鸣牌、翻宝和结算。别人摸的牌只返回 `null`，其他座位的 `hand_count` 也要排除刚摸的那张。
- **适配器负责字段形状，实际数值来自规则模块。** 逐项番数、真实役满倍数和不含本场供托的牌值得从原值取，四个规则开关要回整场生效的完整值。游戏直接读取算点返回对象，避免依赖导入服务器后才会生效的全局函数替换。

`tests/test_http.py` 用本机 HTTP 把首页、预检、错座位、旧对局、摸切、多座位应答和换庄验了一遍。继续加接口时，可以用类似的例子从网页请求一直验到响应。
