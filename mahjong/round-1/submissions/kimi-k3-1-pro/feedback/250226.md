# 给 250226（server.py）的反馈

你提前做了兼容层和跨域处理，方向对；真正的问题是当时没有前端文档，字段只能靠猜。本轮已按正式说明重做适配，并合并老师补丁，原 HTML 无需改动。

必须注意的原问题与修复：

1. 原 `/` 返回 JSON 而不是 `frontend/index.html`；默认端口 5000 且不支持 `--port`。现 `python3 server.py --port 8000` 可直接启动，默认 8000。
2. 状态缺少前端必填的 `rules`，导致红字。现返回四个实际规则值，新游戏也接收并整场保存。
3. 原 `game_id` 固定且不校验。现每局生成新 ID，state/action/next 都核对；旧局允许被新局替换。
4. `players`、`length` 原来被简化或忽略。现严格校验四种 human/bot 配置，支持多人轮流操作及东风/半庄。
5. 吃碰选项、暗/加/明杠结构、waiting_for、viewer 手牌隐藏、hand_count 与 drawn 分离均按页面实际代码适配。
6. 河牌的 `tsumogiri` 不再硬编码 false，action 会传给 game；副露补 `called_tile/from`。
7. `events` 不再固定空数组，按本局顺序返回；别人摸牌的 tile 对 viewer 设为 null。
8. 结算直接使用逐项役番、真实役满倍数与纯手牌 points，删除不完整役表的猜测；流局 reason 使用页面英文枚举。
9. 启动日志改用 ASCII，避免 Windows 控制台代码页让进程在 bind 后因 UnicodeEncodeError 退出。
10. `server_patch.py` 只剩正式入口的兼容包装，避免两份接口逻辑继续漂移。

以后接口完成标准是“按前端校验 + 实际请求 + 语义测试”，不是只返回 200。建议保留当前 `build_state` 纯转换函数，方便不起端口也能测隐藏信息与字段结构。
