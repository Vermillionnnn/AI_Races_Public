# 牌桌前端：接口说明

老师好，前端写好了，就一个 `index.html`，不依赖任何库。下面是它和后端怎么对接。后端用什么语言写都行，只要按这里的格式收发 JSON。

我不懂麻将规则，所以前端**不算任何东西**：能不能吃碰、听什么牌、多少符多少番、点数怎么变，全由后端算好给我，我只负责显示和把玩家点了什么发回去。规则上的事你们自己定。

页面顶上有个格式检查：后端返回的字段和这份说明对不上时，会在页面顶部出一条红色提示，写明缺了哪个字段、哪个值不对，对接的时候看那里就行。

## 上线时怎么启动（必须照这个来）

网站那边的服务器会用下面这条命令启动你们的后端，端口由服务器分配，所以请保证这条命令能直接跑：

```
python3 server.py --port 8000
```

- 在项目根目录执行：`server.py` 放在根目录，这个页面在 `frontend/index.html`。
- `--port` 必须支持，服务器每次给的端口可能不一样；不带参数时默认 `8000`。
- 只监听 `127.0.0.1` 就行，外面有反向代理。
- 启动后 `GET /` 能返回这个页面（HTTP 200）就算起来了。服务器最多等 30 秒，起不来算启动失败。
- 服务器是 Python 3.12，只装了标准库和 Flask，别的库用不了。
- 一个进程要能连续开很多局：每次 `new_game` 给一个新的 `game_id`，旧的局可以不留。
- 每个请求 5 秒内要回。
- 停的时候服务器直接结束进程，不用做清理。程序不能联网，也不要往项目目录外面写文件。

## 怎么跑起来（开发时）

最省事的是后端把 `index.html` 当静态文件放在 `/` 下，接口都挂在同一个域名的 `/api/...`，这样没有跨域问题。

如果后端和页面分开跑，打开页面时加参数指定后端地址，比如 `index.html?api=http://localhost:8000`，这时后端要允许跨域（返回 `Access-Control-Allow-Origin: *`，并且响应 `OPTIONS` 预检）。

另一个参数 `?seed=123` 会在新游戏时把种子传给后端，方便复现同一局。

## 牌怎么写

每张牌是两个字符的字符串：数字 + 花色。

| 写法 | 含义 |
|---|---|
| `1m`–`9m` | 万子 |
| `1p`–`9p` | 筒子 |
| `1s`–`9s` | 索子 |
| `0m` `0p` `0s` | 红五（赤宝牌）。普通的五是 `5m` 等，红五一律写 `0`，不要写成 `5m` |
| `1z`–`7z` | 字牌，依次是 东 南 西 北 白 发 中 |

风也用这套写法：东 `1z`、南 `2z`、西 `3z`、北 `4z`。

座位号 `0`–`3` 是**固定的物理座位**，一局游戏里不变：`0` 是起家（第一局的庄家），`1` 是 `0` 的下家，依此类推。庄家每局会换，当前庄家看 `round.dealer`，每个人当前的自风看 `players[i].seat_wind`。

## 接口一览

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| `POST` | `/api/new_game` | 见下 | 状态（座位 0 的视角） |
| `GET` | `/api/state?game_id=…&seat=n` | — | 状态（座位 n 的视角） |
| `POST` | `/api/action` | `{game_id, seat, type, …}` | 状态（`seat` 的视角） |
| `POST` | `/api/next` | `{game_id, seat, wall?}` | 一局结束后进入下一局，返回状态（`seat` 的视角）。`wall` 可选，测试用，见“指定牌山” |

出错时返回 HTTP 4xx/5xx 和 `{"error": "说明文字"}`，前端会把说明文字弹出来。比如不该这个人操作、打了手里没有的牌，都应该返回 400。

### 新游戏 `POST /api/new_game`

```json
{
  "players": ["human", "bot", "bot", "bot"],
  "length": "tonpuu",
  "seed": 123,
  "rules": { "aka_dora": true, "kuitan": false },
  "wall": ["1m", "1m", "…共 136 张"]
}
```

- `players`：四个座位谁来操作。`human` 是人在页面上点，`bot` 是电脑（电脑怎么打你们定，最简单的摸什么打什么也行）。页面上的“4 人轮流操作”会传四个 `human`，测试用。
- `length`：`tonpuu` 东风战，`hanchan` 半庄战。
- `seed`：可选，随机种子。
- `rules`：可选，规则开关，见下面“规则开关”。
- `wall`：可选，**测试用**，直接指定第一局的牌山，格式见下一节。指定了就不洗牌。

### 规则开关

老师说大家的规则不统一，要做成开关让玩家选。接口我先定好了，新游戏时把开关放进 `rules` 传过去。**页面上的选择界面我还没来得及做**，现在页面只会显示状态里回来的 `rules`；你们要先用的话可以自己在页面上加几个下拉框，按这个格式传就行，别的地方别动。

| 键 | 取值 | 意思 |
|---|---|---|
| `aka_dora` | `true` / `false` | 有没有赤宝牌（每种花色一张红五） |
| `kuitan` | `true` / `false` | 副露以后断幺九算不算役（食断） |
| `kiriage_mangan` | `true` / `false` | 30 符 4 番、60 符 3 番算不算满贯（切上满贯） |
| `renpu_fu` | `2` / `4` | 场风和自风相同的雀头（连风牌）算几符 |

- 没传的键用后端自己的默认值，默认是什么你们定；`rules` 本身也可能是空对象或者不传。
- 传了的键，这一整场都要照着算。
- 状态里要回一个 `rules`，四个键都填上**这一场实际用的值**（包括没传、用了默认的），页面会在牌桌中间显示一行。
- 没有赤宝牌时，牌山里就不应该出现 `0m` `0p` `0s`。

### 指定牌山（测试用）

`wall` 是 136 张牌的数组，顺序是我和老师商量后定的，跟真实的砌牌、取牌方式不一样，只为了好写测试：

- `wall[0:13]` 是座位 0 的配牌，`wall[13:26]` 座位 1，`wall[26:39]` 座位 2，`wall[39:52]` 座位 3。这里的座位一律是**物理座位**，不管这一局谁是庄家。
- 从 `wall[52]` 开始依次是正常摸牌：**当前局的庄家**（`round.dealer`）先摸 `wall[52]`，之后谁摸牌就取下一张。
- 最后 14 张 `wall[122:136]` 是王牌：
  - `wall[122]`–`wall[126]`：宝牌指示牌，开局翻 `wall[122]`，之后每开一次杠依次翻下一张。
  - `wall[127]`–`wall[131]`：对应的里宝牌指示牌。
  - `wall[132]`–`wall[135]`：岭上牌，开杠后依次摸。
- 正常摸牌摸到 `wall[121]` 为止，也就是最多 70 张。每开一次杠，正常摸牌的最后一张就少一张（王牌往前补一张）：开过 k 次杠，正常摸牌只能摸到 `wall[121 - k]`。

第一局的牌山在 `new_game` 里传；之后各局要指定，就在 `POST /api/next` 的请求里带同样格式的 `wall`，规则同上。前端调 `/api/next` 时不传 `wall`，后端照常洗牌。

### 操作 `POST /api/action`

```json
{ "game_id": "g1", "seat": 0, "type": "discard", "tile": "3m", "tsumogiri": false }
```

`type` 和附带的字段：

| `type` | 附带 | 说明 |
|---|---|---|
| `discard` | `tile`，`tsumogiri` | 打一张牌 |
| `riichi` | `tile`，`tsumogiri` | 立直并打出这张（宣言牌） |
| `tsumo` | — | 自摸和 |
| `ron` | — | 荣和 |
| `chi` | `tiles`：手里拿出来的两张 | 吃 |
| `pon` | `tiles`：手里拿出来的两张 | 碰（有红五时用来区分拿哪两张） |
| `minkan` | — | 大明杠 |
| `ankan` | `tile` | 暗杠，`tile` 是杠哪种牌 |
| `kakan` | `tile` | 加杠，`tile` 是加杠的那种牌 |
| `kyuushu` | — | 九种九牌流局 |
| `pass` | — | 不吃不碰不和，跳过 |

- `tsumogiri`：`true` 表示打的是刚摸到的那张（`drawn`），`false` 表示从手牌里打。手牌里有和 `drawn` 一样的牌时，只有靠这个字段才分得清。前端总会带上；没带时后端按“`tile` 和 `drawn` 相同就算摸切”处理。
- 暗杠、加杠的 `tile` 按**牌种**写，五一律写普通的 `5m` / `5p` / `5s`，不写 `0m`（四张五里有没有红五，后端自己知道）。

能做哪些操作由后端在状态的 `legal_actions` 里告诉我，我只显示这些按钮。

**好几个人同时可以操作时**（比如一张牌好几个人都能碰或荣和，`waiting_for` 里有好几个人类座位）：每个座位各自调一次 `POST /api/action`（不要的发 `pass`）。没收齐之前，后端先把已经收到的决定存着，返回的状态仍然是 `playing`，`waiting_for` 里去掉已经回复的人；全部回复后，按 和 > 碰/杠 > 吃 的优先级一起处理。

电脑玩家的操作后端自己处理：收到人的操作后，后端把电脑该做的都做完，**一直跑到又需要某个人做决定、或者这一局结束**，再返回。

## 状态

每个接口都返回同一种状态对象，是某一个座位（`viewer`）看到的样子：别人的手牌看不到。

```json
{
  "version": 1,
  "game_id": "g1",
  "phase": "playing",
  "round": { "wind": "1z", "number": 1, "honba": 0, "riichi_sticks": 0, "dealer": 0 },
  "dora_indicators": ["3p"],
  "wall_left": 69,
  "viewer": 0,
  "turn": 0,
  "waiting_for": [0],
  "rules": { "aka_dora": true, "kuitan": true, "kiriage_mangan": false, "renpu_fu": 4 },
  "players": [
    {
      "seat": 0, "name": "你", "score": 25000, "seat_wind": "1z", "riichi": false,
      "discards": [],
      "melds": [],
      "hand_count": 13,
      "hand": ["1m", "2m", "3m", "0p", "6p", "7p", "2s", "3s", "4s", "5z", "5z", "7z", "7z"]
    },
    { "seat": 1, "name": "电脑 1", "score": 25000, "seat_wind": "2z", "riichi": false,
      "discards": [], "melds": [], "hand_count": 13 },
    { "seat": 2, "name": "电脑 2", "score": 25000, "seat_wind": "3z", "riichi": false,
      "discards": [], "melds": [], "hand_count": 13 },
    { "seat": 3, "name": "电脑 3", "score": 25000, "seat_wind": "4z", "riichi": false,
      "discards": [], "melds": [], "hand_count": 13 }
  ],
  "drawn": "8p",
  "legal_actions": [
    { "type": "discard", "tiles": ["1m", "2m", "3m", "0p", "6p", "7p", "8p", "2s", "3s", "4s", "5z", "7z"] }
  ],
  "hints": {
    "waits": [],
    "furiten": false,
    "discards": {
      "0p": [{ "tile": "5z", "left": 2 }, { "tile": "7z", "left": 2 }],
      "8p": [{ "tile": "5z", "left": 2 }, { "tile": "7z", "left": 2 }]
    }
  },
  "events": [
    { "type": "draw", "seat": 0, "tile": "8p" }
  ],
  "result": null
}
```

字段说明：

- `phase`：`playing` 进行中；`round_end` 这一局结束了，`result` 里是结算，等点“下一局”；`game_end` 整场结束，`result` 是最后一局的结算。
- `round`：`wind` 场风（`1z` 东场、`2z` 南场）；`number` 第几局（1–4）；`honba` 本场数；`riichi_sticks` 场上的供托（立直棒）根数；`dealer` 当前庄家的座位号。
- `dora_indicators`：已经翻开的宝牌**指示牌**（不是宝牌本身，我只是照着显示）。
- `wall_left`：还能正常摸的牌数（不算王牌）。
- `viewer`：这份状态是谁的视角。
- `turn`：现在轮到谁（摸牌、打牌的那个人）。
- `rules`：这一场实际用的规则开关，四个键都要有，格式见“规则开关”。
- `waiting_for`：现在在等哪些座位做决定。打牌后别人可以鸣牌或荣和时，这里会有好几个人；只有其中有人类玩家时后端才会停下来返回。
- `players[i]`：
  - `score` 当前点数（一局结束时已经是结算后的点数）。
  - `seat_wind` 这一局的自风。
  - `riichi` 是否已立直。
  - `discards` 河，按顺序，每项 `{ "tile": "3m", "tsumogiri": false, "riichi": false, "called": false }`：`tsumogiri` 是不是摸切；`riichi` 是不是立直宣言牌（我会横着放）；`called` 是不是被别人吃碰杠拿走了（我会显示成半透明，但仍留在河里）。
  - `melds` 副露，每项 `{ "type": "pon", "tiles": ["5m", "5m", "0m"], "from": 2, "called_tile": "0m" }`：`type` 是 `chi` / `pon` / `minkan` / `ankan` / `kakan`；`tiles` 是这组的全部牌（杠是 4 张）；`from` 从谁那里鸣的（暗杠为 `null`）；`called_tile` 鸣的是哪一张（暗杠为 `null`）。加杠就是把原来的碰改成 `kakan`、`tiles` 变 4 张。
  - `hand_count` 手牌张数（不含副露，不含 `drawn`）。
  - `hand` **只有 `viewer` 自己有**，其他人不要给。是手牌（不含副露），**不含刚摸的那张**；顺序后端排好，我照着显示。
- `drawn`：`viewer` 刚摸到、还没打出的那张，没有就是 `null`。我会把它和手牌隔开一点显示。吃碰之后没有摸牌，`drawn` 为 `null`，这时 `hand` 是 14 − 3×副露数 张。
- `legal_actions`：`viewer` 现在能做的操作，不该他操作时是空数组。
  - `{ "type": "discard", "tiles": [...] }`：能打的牌（同种牌写一次；红五和普通五分开写）。
  - `{ "type": "riichi", "tiles": [...] }`：能立直，`tiles` 是打哪些牌可以立直。
  - `{ "type": "chi", "options": [["4m", "6m"], ["6m", "7m"]] }`、`{ "type": "pon", "options": [["5m", "5m"], ["5m", "0m"]] }`：每个选项是手里拿出来的两张，只有一个选项我就直接发，多个我让玩家选。
  - `{ "type": "ankan", "tiles": ["1z"] }`、`{ "type": "kakan", "tiles": ["5m"] }`：可以杠哪些，按牌种写，五写 `5m` 不写 `0m`（同上）。
  - `{ "type": "minkan" }`、`{ "type": "tsumo" }`、`{ "type": "ron" }`、`{ "type": "kyuushu" }`、`{ "type": "pass" }`。
- `hints`：给 `viewer` 的听牌提示，不需要时可以是 `null`。
  - `waits`：现在（13 张时）听哪些牌，每项 `{ "tile": "3m", "left": 2 }`。按**牌种**列，听五时只列一条 `5m`（不拆成 `5m` 和 `0m`），`left` 是普通五和红五合计，最多 4。它是**从这个人看来**还剩几张（自己手里的、所有人河里的、副露里的、翻开的宝牌指示牌都要扣掉）。没听牌就是空数组。
  - `furiten`：是否振听。
  - `discards`：轮到 `viewer` 打牌时（手里 14 张），打哪张之后能听牌、听什么，键是牌（和 `legal_actions` 里能打的牌写法一致，红五是 `0m`）、值的格式同 `waits`。打了不能听牌的不用列。我会在这些牌下面画蓝线，鼠标移上去显示听什么。
- `events`：**这一局从开始到现在**的全部事件，按顺序，我只显示最后几十条。每项：
  - `{ "type": "draw", "seat": 1, "tile": null }`：摸牌。`tile` 只有摸牌的人是 `viewer` 时才给，否则 `null`。
  - `{ "type": "discard", "seat": 1, "tile": "3m", "tsumogiri": true }`
  - `{ "type": "riichi", "seat": 1 }`（后面紧跟一条 `discard`）
  - `{ "type": "chi" | "pon" | "minkan", "seat": 2, "tiles": [...], "from": 1 }`
  - `{ "type": "ankan" | "kakan", "seat": 2, "tile": "5m" }`
  - `{ "type": "dora", "tile": "7s" }`：新翻的宝牌指示牌。
  - `{ "type": "tsumo", "seat": 0 }`、`{ "type": "ron", "seat": 0, "from": 3 }`
  - `{ "type": "ryuukyoku", "reason": "exhaustive" }`
  - 其他类型我会原样显示 JSON，不会报错。
- `result`：进行中为 `null`，一局结束后见下一节。

## 结算 `result`

和了：

```json
{
  "type": "agari",
  "wins": [
    {
      "seat": 0,
      "from": 2,
      "hand": ["2m", "3m", "4m", "0p", "6p", "7p", "2s", "3s", "4s", "5z", "5z", "7z", "7z"],
      "melds": [],
      "win_tile": "7z",
      "yaku": [
        { "name": "立直", "han": 1 },
        { "name": "役牌 中", "han": 1 },
        { "name": "赤宝牌", "han": 1 }
      ],
      "han": 3,
      "fu": 40,
      "yakuman": 0,
      "points": 5200
    }
  ],
  "dora_indicators": ["3p"],
  "uradora_indicators": ["9s"],
  "delta": [5200, 0, -5200, 0]
}
```

- `wins`：和了的人，一般一个；一炮双响时有两个。
  - `from`：放铳的座位，自摸为 `null`。
  - `hand`：和了时的手牌，**不含和了的那张**；`win_tile` 单独给。`melds` 格式同上。
  - `yaku`：役种列表，`name` 我原样显示，用什么名字你们定。宝牌、赤宝牌、里宝牌也请作为一项列进来（`han` 写张数），这样玩家能看到番数是怎么加起来的。
  - `han`：总番数，等于 `yaku` 里各项 `han` 之和。
  - `fu`：符数。
  - `yakuman`：役满倍数，不是役满就是 `0`。役满时我不显示符和番，只显示“役满”或“2 倍役满”和点数，但字段格式不变：`yaku` 每项的 `han` 仍然要是数字，单倍役满的役写 `13`、双倍役满的役写 `26`；`han` 是它们的和；`fu` 也要是数字（随便写，比如 `0`，我不显示）。
  - 累计役满（不是役满牌型，番数加起来 13 番以上）：`yakuman` 写 `0`，`han`、`fu` 和各役的番数照常写，我会照常显示符番，`points` 按役满的点数写。
  - `points`：这手牌本身值多少点（比如 5200、自摸时就写合计，比如 2000/4000 写 8000），**不含本场和供托**，只是显示用。
- `dora_indicators` / `uradora_indicators`：结算时的宝牌指示牌和里宝牌指示牌（没有里宝时为空数组）。
- `delta`：四个座位这一局的点数变化，按座位号排列，**本场、供托、立直棒都算进去**，和了的人拿走的场上供托也算在他的 `delta` 里，所以四项加起来等于 1000 × 拿走的供托根数（没有供托时就是 0）。立直时交的 1000 点在立直那一刻就从 `score` 里扣掉、加进 `round.riichi_sticks`，不算在 `delta` 里。

流局：

```json
{
  "type": "ryuukyoku",
  "reason": "exhaustive",
  "tenpai": [true, false, false, true],
  "delta": [1500, -1500, -1500, 1500]
}
```

- `reason`：`exhaustive` 荒牌流局；`kyuushu` 九种九牌；`four_kans` 四杠散了；`four_riichi` 四家立直；`four_winds` 四风连打；`triple_ron` 三家和了。规则上采不采用哪些，你们定。
- `tenpai`：荒牌流局时各家是否听牌，其他流局可以不给。
- `delta`：同上。
