# 给 250226（server.py）的反馈

在没拿到前端说明的情况下，你把几个人对不上的格式（score 的 dict、hints 没人算）都在 server 里兜住了，而且没去改别人的源码，思路是对的。用标准库 http.server 不依赖 Flask 也很好。主要问题是和前端说明（后来才发）对不上，所以这次 server.py 基本按说明重写了，你可以对照着看。

## 和说明不一致、会导致上线失败的

1. **启动方式**：服务器会用 `python3 server.py --port 8000` 启动。原版不认 `--port`，默认端口 5000、读的是环境变量 `PORT` → 上线直接起不来。已用 `argparse` 支持 `--port`，默认 8000。
2. **`GET /` 要返回 `frontend/index.html`**（服务器靠这个判断“起来了”），原版返回的是一段 JSON。
3. **只有一个全局对局**：两个人同时打会互相覆盖，`game_id` 也没有。已改成按 `game_id` 存在 dict 里，旧的超过 200 局自动丢掉；加了锁，并发请求不会把同一局打乱。
4. **字段名**：`seat`/`current`/`remaining`/`game_over`/`ok` 这些都要换成说明里的 `viewer`/`turn`/`wall_left`/`phase` 等，还要有 `waiting_for`、`rules`、`events`。

## 逻辑上的

5. `new_game` 只把 `seat` 这一个座位设成人类，说明里是用 `players` 数组（四人测试模式会传四个 `human`）。
6. 没检查“该不该这个人操作”、“这个座位是不是电脑”，应该返回 400。
7. 出错时说明要求 `{"error": "..."}`，原版还多了 `ok` 字段（不影响，但没必要）。
8. 听牌提示 14 张时只给 `discards`，没给 `furiten`；前端要求 `waits` 是 `[{tile, left}]` 数组，不是 dict。

## 小建议

- `_normalize_action` 里把 `hu` 猜成 tsumo/ron 是好意，但接口有明确的 `type`，猜测反而可能掩盖前端的 bug，这次删掉了。
