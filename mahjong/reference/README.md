# 参考实现

本目录是一份独立编写的标准立直麻将后端实现，不进选手包。它有三个用途：标定学生原代码里的 bug、在隐藏测试中作为算点对拍与流程对拍的标准答案，以及在 round-2 前端审美赛（和未来的 AI 对局赛）里直接充当后端。

实现完全依据 [`规则.md`](规则.md)，HTTP 与 JSON 接口严格遵循 [`接口说明.md`](../club-project/frontend/接口说明.md)，仅依赖 Python 3.12 标准库，不引入第三方库。

| 文件 | 说明 |
|---|---|
| [`规则.md`](规则.md) | 参考规则文档，把默认规则逐条写清，并将日麻中常见有争议的规则变体整理成开关表（判分时选手选用其中任意一种都算对） |
| [`server.py`](server.py) | HTTP 服务入口，提供 `/` 页面托管以及 `/api/new_game`、`/api/state`、`/api/action`、`/api/next` 四个接口，支持 CORS 与 OPTIONS 预检，非法请求统一返回 4xx 和 `{"error": ...}` |
| [`game.py`](game.py) | 整场对局管理，负责局数推进、换庄与连庄、本场计算、结束条件判断（击飞、末局庄家第一、南入/西入延长、剩余供托归属），以及驱动电脑玩家自动行动 |
| [`kyoku.py`](kyoku.py) | 单局状态机，处理摸牌打牌、吃碰杠、抢杠、杠宝牌翻开、立直与一发、各类振听、多人同时可鸣牌或荣和时的分批等待与优先级结算，以及和了与流局结算 |
| [`view.py`](view.py) | 负责将内部状态组装成某个指定视角（`viewer`）看到的 JSON 对象，包括合法操作列表、听牌提示、事件流水以及对手手牌的隐私屏蔽 |
| [`tiles.py`](tiles.py) | 牌的编码格式、牌种编号、排序规则以及宝牌指示牌换算 |
| [`agari.py`](agari.py) | 和牌判定、手牌拆法枚举、听牌列表以及向听数计算 |
| [`yaku_fu.py`](yaku_fu.py) | 针对某一种具体手牌拆法，计算对应的役种、番数、符数与役满倍数 |
| [`score.py`](score.py) | 在所有合法拆法中按高点法挑出最有利的结果，计算基本点、满贯以上封顶以及各家付点（含本场费与包牌分摊） |
| [`rules.py`](rules.py) | 全部规则开关的键名定义、默认值与参数校验 |
| [`bot.py`](bot.py) | 参考后端内置的电脑玩家出牌逻辑 |
| [`tests/`](tests/) | 完整自测套件（共 118 项），包含算点单元测试、按剧本推进的流程测试（进程内与 HTTP 各跑一遍）、随机整场压力测试以及前端 `checkState` 格式校验 |

## 启动方式

```bash
cd mahjong/reference
python3 server.py --port 8000            # 默认端口 8000，仅监听 127.0.0.1
python3 server.py --port 8000 --page 路径/index.html
```

- `GET /` 默认返回牌桌页面：优先使用 `--page` 指定的文件；未指定时先找上一级目录的 `frontend/index.html`（round-2 选手包里后端放在 `backend/`、页面在旁边的 `frontend/`），若不存在则回退到 `../club-project/frontend/index.html`。页面路径在载入模块时就定好，截图工具（`tools/http_bridge.py`）把 `server.py` 当模块载入时也能返回页面。
- 单个服务进程支持连续开启多局游戏（内存中最多保留最近的 2000 局）。
- 请求 `/api/new_game` 时若省略参数，`players` 默认为 `["human", "bot", "bot", "bot"]`，`length` 默认为 `tonpuu`（东风战）。

## 规则开关

调用 `POST /api/new_game` 时，可在请求体的 `rules` 字段中传入需要调整的规则开关；未传入的键自动使用默认值，遇到未知键名或非法取值时返回 400。后端每次返回的状态里会在 `rules` 中完整回显全部开关（前端页面的 `checkState` 只校验最常用的四个开关，多出的字段会被安全忽略）。

| `furiten_no_yaku` | `true`（漏掉无役的听牌也算振听，见下） | `false`（仅漏掉实际能荣和的牌才算振听） |

### 在 `规则.md` 之外补充敲定的两条规则

- **`furiten_no_yaku`**：当手牌听张但别人打出的那张牌没有役（因此实际上无法荣和）时，漏掉它是否触发同巡振听或立直振听。默认开启 `true`（与常见线上平台一致）；设为 `false` 时，只有当时确实能荣和却选择不和才算振听。
- **立直棒的扣除时机**：立直宣言牌未被荣和时才扣除 1000 点并放上供托（此项不做开关）。如果出现三家和了流局，宣言牌视同被荣和，立直不成立、不扣这 1000 点。

### 实现时选定的细部处理（`规则.md` 未展开说明的部分）

- **空听不算听牌**：如果某张听牌的四张全在自己手里，就不把它计入听牌；这项规则在立直资格、振听判定、听牌提示 `hints` 和荒牌流局听牌料中保持完全一致。
- **海底牌与鸣牌限制**：正常牌山摸完（`wall_left` 归 0）后打出的最后一张牌不能吃、碰、杠；`wall_left` 为 0 时也不能暗杠或加杠。吃碰之后必须先打出一张牌，不能接着直接开杠。如果某次吃碰在“禁止食替”下会导致无牌可打，服务端直接不提供该吃碰选项。
- **连续开杠的翻宝顺序**：如果前一次明杠或加杠还欠着一张延迟翻开的杠宝牌，紧接着再开新杠时，会先把前一次欠的杠宝翻开，再处理新的杠。
- **抢暗杠的振听边界**：只有国士无双可以抢暗杠；因此国士听牌时漏掉别家暗杠的牌会计入振听，但普通牌型恰好听那张牌时不算漏和。
- **包牌的本场费与复合役满**：涉及包牌的役满，如果自摸和了，本场费由包牌者全付；如果由第三家放铳，则放铳者与包牌者各付一半（每本场各付 150 点）。复合役满中只有带包的那部分役满按包牌规则付点，其余倍数仍按正常方式结算。
- **一炮双响与连庄**：一炮双响的几位和牌者中只要包含当前庄家，就按连庄处理且本场数加 1。
- **延长战与末局终局条件**：开启南入或西入后，进入延长局时只要有人点数达到 30000 分即结束整场；此时“末局庄家第一就结束”也额外要求庄家点数达到 30000 分。
- **终局剩余供托**：开启 `leftover_sticks_to_top` 时，剩余供托会计入最后一局的 `result.delta` 和最终点数，同时在 `result.leftover_sticks` 中标明归属座位与根数。
- **流局满贯**：开启后，达成流局满贯时替代荒牌听牌料结算，不附带本场费；是否连庄仍看庄家本局是否听牌。
- **立直状态标志**：`players[i].riichi` 只有在立直宣言牌未被荣和、立直正式成立之后才变为 `true`。
- **听牌提示 `hints`**：轮到自己打牌（14 张牌状态）时，`waits` 为空数组、`furiten` 为 `false`，仅提供 `discards`（打出哪张能听什么）；其余时刻（13 张牌状态）提供当前听牌 `waits` 与振听标志 `furiten`。
- **附加的扩展字段**（前端会安全忽略）：岭上摸牌产生的 `draw` 事件带有 `"rinshan": true`；包牌结算时 `result.wins[i].pao` 记录包牌座位；整场结束时 `result.final` 记录最终点数与名次；流局满贯时 `result.nagashi` 记录触发座位。
- **电脑玩家策略**：能和牌必和、能九种九牌流局就流局；其余时刻优先打出能使向听数最小、有效进张最多的牌（同效时先打孤张客风与幺九牌，尽量留宝牌和红五）；门清听牌就立直；副露只碰役牌，不开杠。

## 运行自测

```bash
cd mahjong/reference
python3 -m unittest discover -s tests                        # 运行全部测试，约耗时 1 分钟
python3 -m unittest discover -s tests -p test_score.py       # 仅运行算点单元测试
STRESS_GAMES=100 STRESS_HTTP=5 python3 -m unittest discover -s tests -p test_stress.py   # 加大压力测试规模
```

- **`test_score.py`**：覆盖所有役种、符的各类来源、点数表各档位（含 4 番 40 符 8000、3 番 70 符 8000、30 符 4 番 7700 与切上满贯 8000、60 符 3 番）、累计役满、单倍与双倍/复合役满（含天和九莲 3 倍）、宝牌/赤宝/里宝、本场费与包牌付点，并随机校验和牌判定、拆牌枚举和向听数之间的一致性。
- **`test_flow.py`**：借助 `judge/harness.py` 拼接牌山并按剧本推进整局，逐项测试立直宣言牌被荣和、立直与一发、两立直、一炮双响（本场和供托归离放铳者最近的一家）、头跳、三家和了、抢杠、国士抢暗杠、三种振听与 `furiten_no_yaku`、荒牌听牌料、庄家听牌连庄、换庄后 `/api/next` 带牌山按物理座位发牌、四种途中流局、杠宝翻开时机、食替、碰优先于吃及多人分批表态、红五暗杠、`hints` 剩余张数、包牌、流局满贯、四个接口开关与非法请求 400 返回；进程内测试还额外覆盖击飞、末局庄家第一、末局闲家和了、剩余供托归属、半庄进入南场以及南入。同一套剧本会另起服务走 HTTP 再跑一遍，最后若环境装有 Node，还会用前端的 `checkState`（`tests/check_state.js`）校验全部返回状态。
- **`test_stress.py`**：四个座位随机执行合法操作（多数时候优先打向听数最小的牌）打完整场，同时随机组合规则开关，持续校验点数守恒、牌数守恒、可见牌不超过 4 张、视角隐私、`wall_left` 单调不增、合法操作均被接受、非法操作返回 400 且不破坏状态、番数合计与点数一致、`delta` 与实际点数变化一致以及 `checkState` 格式无误；另运行人机混合局和四电脑整场对局，记录每局请求耗时。
