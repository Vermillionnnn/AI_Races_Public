# 学生原件的 bug 清单（2026-11-23 整理）

> 隐藏测试第一部分“已知 bug 的复现用例”的清单。底稿是满分试跑二列的 44 条缺陷加 4 项开关缺失（[`trial-2/试跑记录.md`](../submissions/trial-2/试跑记录.md)，括号里的 `#n` 是它的编号）；子代理又读了试跑一、六份正式提交的反馈和评委说明、`交差记录.md` 的外部评审，逐条对照 [`club-project/`](../club-project/) 原件核过，补了 1 条（I8），剔掉了误报。
>
> “判定”一列：**测**＝无争议 bug，写复现用例；**变体**＝[`规则.md`](../reference/规则.md) 第 8 节里两种都算对，只查程序前后一致、和选手自己的规则文档一致；**不测**＝从 HTTP 接口上触发不了（只能直接调模块）或影响很小。
> “原件”一列记录老师补丁入口 `PORT=N python3 server_patch.py` 的 HTTP 实测结果。“待跑”表示还缺复现。W5、W7 的补测增加了关键断言，历史结果仍对应当时的脚本。见 [复现结果](复现结果.md)。
>
> 除座位配置用例外，四个座位都是人类。未指定的决定默认摸切、pass。补测在原件上按 W1、W2 调整相应的岭上牌和配牌位置，以便复现同一局面。其余牌山位置按 [接口说明](../club-project/frontend/接口说明.md#指定牌山测试用)。

### 暗杠后只听不存在的第五张

关赤宝牌，庄家配 `5555m 46m 123p 789s 6z`，开局摸 `6z`，暗杠 `5m` 后岭上摸 `7z`。打掉 `7z` 的剩牌只能用第五张 `5m` 才成形。立直选项、弃牌提示和打出后的听牌提示都应排除这条，摸切到荒牌时庄家的 `tenpai[0]` 为 `false`。把暗杠改成四张 `2m`，其余牌和操作相同，此时确实听 `5m`，可以立直，荒牌也算听牌。

原件和九份提交在第一手都判不听。参考后端在第一手仍提供立直、提示 `5m left=0`，荒牌也判听。

> **设计者 2026-11-23：参考后端这样不算错。** 天凤明文“形式聴牌あり、5牌目を待つ聴牌あり”（[天鳳マニュアル](https://tenhou.net/man/)），听第五张算形式听牌，荒牌照样收听牌料。这一条按规则变体处理：判听、判不听都算对，只要程序前后一致（立直选项、听牌提示、荒牌判定三处说法一样）。下面原来的“排除第五张”只是另一种取法。

原记录：参考的听牌计算只按暗手的张数排除第五张，没计入自己杠里的四张。[参考听牌计算](../reference/kyoku.py#L84) [参考立直选项](../reference/kyoku.py#L227) [荒牌判定规则](../reference/规则.md#3-一局)

## 不测、误报

- **只能直接调模块才看得到**（从 HTTP 上触发不了）：`score` 返回 dict、`game` 按元组拆导致一和牌就崩（#7，被 `server.py` 的猴子补丁兜住了）；`can_hu` 单独调用时错误副露也能抵牌（#44）；红五和了张不在手里时返回 0 番、`fu`/`tenpai` 不校验非法牌、`score` 在 0 番时字段不全（`game.py` 的调用方式碰不到）。
- **误报**：立直后暗杠改变面子构成仍允许（参考规则只要求听的牌不变）；同巡振听应在摸牌时解除（参考规则写的是“下一次打牌之前”，原件正好如此）；三家和了应扣宣言者的立直棒（宣言牌被荣和则立直不成立）；宣言牌被鸣后下一张应横放（接口说明把 `riichi` 定义为宣言牌本身）；“106 局只有 1 局和牌”（电脑只会摸切，不是和牌判断坏了）。

## 待设计者定

1. **没役时漏掉和了张，算不算同巡振听**（原件 `game.py` 第 512–516 行只在有 `ron` 选项时才置振听）。参考规则写的是“别人打出了你**能荣和**的牌而你没和”，字面上支持原件；常见线上规则按听的牌算、不管有没有役。Opus High、Gemini 和外部评审都把它当 bug。
2. **立直棒什么时候扣**：接口说明写“立直时交的 1000 点在立直那一刻就从 `score` 里扣掉”，参考规则写“这张牌没有被荣和，立直才成立：扣 1000 点”。原件和底稿 #15 按参考规则。两种只在“宣言牌打出后、别人还没决定荣不荣和”那一刻看得出差别，建议隐藏测试不在这个时刻断言 `score`。
3. **I15 立直后点同值手牌被拒**：算后端的 bug（应按摸切处理），还是接口说明没说清、不计分。
