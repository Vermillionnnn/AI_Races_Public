# 隐藏测试

本目录是 round-1 正确性与一致性的客观判分工具，不进选手包；测试不直接引用或检查选手的内部代码，而是统一按照上线约定启动选手的后端服务，全部通过前端定义的 HTTP 接口（见 [`接口说明.md`](../player-kit/frontend/接口说明.md)）发请求：开局时把四个座位都设为人类玩家，并通过指定牌山精确构造局面。

| 文件 | 说明 |
|---|---|
| [`bug清单.md`](bug清单.md) | 学生原件里的已知 bug 清单，记录每条问题的编号、现象、归属、触发方式、是否纳入评分（必测 / 规则变体 / 不测）以及在原件上是否能复现；文末附有几处待确认条目 |
| [`cases.py`](cases.py) | 已知 bug 的复现测试用例（编号与 `bug清单.md` 一一对应），每道用例的牌例和手算核对过程都写在代码注释里 |
| [`run.py`](run.py) | 复现用例运行入口：`python3 mahjong/judge/run.py [选手目录名…] [-k 用例编号…]`。默认同时运行学生原件和 round-1 全部提交，在终端打印“用例 × 选手”结果表，并把详细失败原因写入被忽略的 `out/` 目录；round 1.5 的提交点名时加后缀 `@r1.5`（如 `kimi-k3-1-pro@r1.5`），`crosscheck.py` 同 |
| [`复现结果.md`](复现结果.md) | 九份提交运行已知 bug 复现用例与稀有规则回归用例后的汇总表和解读 |
| [`crosscheck.py`](crosscheck.py) | 算点对拍脚本：随机生成各类和牌局面（覆盖门清与碰牌、庄闲、自摸与荣和、立直/两立直/一发、宝牌与赤宝牌，以及四个规则开关的随机组合），以参考后端的结算为基准，比对各份提交返回的番数、符数、役满倍数、单手点数和 `delta`。运行命令：`python3 mahjong/judge/crosscheck.py -n 2000 [选手…]`，样本完全由随机种子决定。每个样本在每份程序上的结果缓存在忽略的 `out/cc-cache/`，按程序代码指纹分文件，改了程序或跑法自动失效，重跑只算没缓存的；`--no-cache` 关掉 |
| [`问题总表.md`](问题总表.md) | 复现用例、对拍、规则变体三处查出的 bug 和客观问题合成一张表（问题 × 选手），分算点、流程、接口、显示四类 |
| [`对拍结果.md`](对拍结果.md) | 正式一轮算点对拍（2058 个有效样本）的汇总结果、按错误类别的逐项裁决，以及剔除规则变体后的真 bug 统计 |
| [`变体一致性.md`](变体一致性.md) | 规则变体一致性：用 V 组探测用例查出各家程序实际采用哪种变体、是否与各自的规则文档一致，以及设计者对三处争议的决定和由此产生的扣分 |
| [`checkstate.py`](checkstate.py) | 将前端 `index.html` 里的 `checkState` 格式检查照搬到 Python，测试过程中每次接口返回状态都会过一遍（对应 bug 清单中的 I3） |
| [`harness.py`](harness.py) | 测试底座，负责按规范启动和停止后端进程（选手按 `python3 server.py --port N` 启动；学生原件则按老师的跑法 `PORT=N python3 server_patch.py` 启动，用来确认原件确实会触发这些 bug）、拼接指定牌山以及按剧本推进整局对局 |

## 测试分成两部分（2026-11-23 定稿）

1. **已知 bug 的复现用例**：针对学生原件里的每个已知 bug，专门拼出一手必定触发它的牌局——先在原件上确认会出错，再去跑每位选手的提交，检查他们有没有修好。完整条目见 [`bug清单.md`](bug清单.md)。
2. **随机对拍**：专门用来抓“选手改代码时不小心引入的新 bug”（例如 Qwen 拆分切上满贯开关时把原本好好的满贯封顶修丢了，而只盯着原件缺陷的复现用例覆盖不到这类回归）。对拍包含两块：
   - **算点对拍**：随机生成大量和牌局面（覆盖门清、副露、各类役种、符的各种来源、宝牌、庄闲、自摸荣和及四个开关的组合），拼成牌山打到和了，比对结算里的 `han`、`fu`、`yakuman`、`points` 和 `delta`。标准答案由 [`reference/`](../reference/) 下的参考后端给出。
   - **流程对拍（待补）**：随机打完一整场对局，重点检查流程不变量（点数守恒、牌数守恒、`legal_actions` 与服务端实际接受的操作一致、视角隐私不泄露、`wall_left` 递减以及状态格式检查），不强求每步随机走向一致。
   - 只要各份提交之间、或提交与参考后端之间出现分歧，就逐类对照 [`参考规则`](../reference/规则.md) 手算裁决；属于规则开关（第 8 节）范围内的变体差异，按选手自己选择的那一版核对，不扣正确性分。
