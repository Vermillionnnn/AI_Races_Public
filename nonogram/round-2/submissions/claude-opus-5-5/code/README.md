## 编译和运行出题器（PowerShell）

```
g++ -O2 -std=c++20 gen.cpp -o gen.exe
```

```
.\gen.exe <种子> <题数> <行数> <列数> <每题爬山秒数> <题号前缀> [试填预算] [初始密度] [目标估算秒数]
```

选题：5 个进程共出 136 道。stderr 日志里有每道题的估算秒数，按它从高到低取前 120 道，
入选题的估算最低 18.7 秒。这一步只用我自己的估算，没有用 `测速.py`。

每个进程输出 `<前缀>_puzzles.txt`、`<前缀>_answers.txt`，每道题的估算写在 stderr。
结果依赖计时（爬到时限或目标就停），同一种子不保证逐位复现。

## 怎么出的题

1. **读乌龟**：它是“位并行单行推理 + 传播 + 两色试填到不动点 + DFS”。试填找不出矛盾时只能猜，
   每个搜索节点都要把所有未知格重新试填一遍，而且它是纯 Python。所以最费它时间的是：**试填推不动、
   必须深搜，而且搜索树里有很多走错的分支**的题。
2. **爬山**：随机生成密度约 0.5 的网格，先找到一个唯一解的起点；之后每步随机翻转 1–2 格，
   只要新网格仍然**唯一解**且难度**不下降**就接受，否则撤销。到达目标难度或每题 25 秒时限就停。
3. **难度指标 = 模拟乌龟**：用 C++ 按乌龟的策略找第一个解。这里的策略指：行按未知格少的先试、
   格从左到右、按 (较弱一边收益, 较强一边收益) 字典序选分支格、推出多的一边先试、解出即停。
   统计三样：不同行状态数（乌龟每行一个不淘汰的 dict，所以这就是它真正调用单行推理的次数）、
   行访问次数、试填次数。再按粗略的 CPython 成本（新行状态 20 µs、每次行访问 1.5 µs、每次试填 15 µs）
   折成秒数。目标 25 秒，是 10 秒上限的 2.5 倍，给成本模型留出误差。
4. **尺寸**：22×22 和 25×25。大尺寸（45×45）的随机图多半多解；高密度起点又是单行可解的平台，
   单格翻转爬不动（日志里 45×45、40×40、28×28 都试过）。中等尺寸爬山很快，几秒到十几秒
   就能爬到乌龟要猜几百次的程度。

## 怎么保证唯一解

- **穷举数解**：完整的试填 + DFS，两个分支都搜，数到第 2 个不同的解就停。试填推理只用可靠规则：
  一边矛盾就定另一边；两边都可行时取交集。所以搜完整棵树只找到 1 个解，就证明了唯一。
  每次爬山接受前都跑这一步。题目写出前，再用 4 倍预算（480 万次试填）复核一次，
  并核对这个唯一解就是生成它的网格。
- **行推理正确性**：与暴力枚举交叉验证，30 万条随机线（长度 1–14，含无解线索、随机已知格），
  可行性判断和推出的每一格全部一致。
- 这套行推理和传播代码在第一轮正式题上 120/120 全对。
- 每道题的穷举证明都在 120 万次试填以内完成（C++ 约 1 秒级），判分方的证明程序不会跑不完。
- 交卷前另写一个复核程序，从 `题目.txt`、`答案.txt` 重新读入每道题，用 2000 万次试填的预算再证一遍唯一解，
  并核对答案与唯一解一致：120/120 通过。
- `检查.py`：通过，120 道题，答案都满足线索。
