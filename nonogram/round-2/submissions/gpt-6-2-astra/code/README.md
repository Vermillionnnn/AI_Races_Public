# 第二轮 · 黑段端点题集

`题目.txt` 和 `答案.txt` 是参赛文件，共 120 题。每题来自不同的生成种子。只凭题目中的行、列线索，就能证明所有黑段的位置。

## 生成和复核

在本目录打开 PowerShell。第一条命令只读取已有题目和答案，逐题证明唯一解；第二条在新目录内从种子重新生成整套文件。出题器只用 Python 标准库。

```powershell
py -3.13 generate.py --verify-only
py -3.13 generate.py --output ./reproduced
py -3.13 ../../../prompt/检查.py 题目.txt 答案.txt
```

## 唯一性证明

把一行中的一个黑段写成左闭右开的区间 `[a,b)`。宽为 `w` 的棋盘有 `w+1` 个列边界，编号从 0 到 `w`。令 `m_j` 为第 `j` 列的黑格总数，直接对该列线索求和即可得到。左右两侧的虚拟列均有 0 个黑格。

在边界 `j` 处，设 `s_j` 个黑段开始、`e_j` 个黑段结束。从左边一列移到右边一列，黑格总数的变化满足

```text
d[j] = m[j] - m[j-1] = s[j] - e[j]
s[j] >= max(d[j], 0)
```

所有行线索的块数之和 `R` 就是全盘的黑段数，因此也等于所有 `s_j` 之和。对这批题，检查器先从线索核实 `R == sum(max(d[j], 0))`。既然上述不等式逐项成立且两边总和相等，每一项都必须相等。所以黑段只能在正差边界开始，在负差边界结束；零差处不能有黑段开始或结束。

现在单看一行。长度为 `k` 的块，其起点 `a` 必须满足 `d[a] > 0` 且 `d[a+k] < 0`。按线索顺序从左向右，每次取能与上一个块隔开至少一格的最早起点，得到一组最早位置。从右向左同理得到最晚位置。任何合法解的每个块都夹在对应的最早、最晚位置之间。检验程序逐行核实两组位置完全相同，因此每行只有一种可能。再核对重建网格的全部列线索和提交答案，即同时证明了解的存在性与唯一性。对于转置出的题，交换行列即可；`--verify-only` 自动尝试两个方向。

## 出题方法与难度

出题器先在列边界选择互不相交的起点集合与终点集合，拼出若干组互不接触的区间作为候选行。它用动态规划计算每串块长有几种摆法，只选在这些端点上恰好有一种摆法的行。不同种子改变棋盘尺寸、端点、行的组合和列黑格数的分布。活动行之间插入全白行，部分棋盘再转置。

白行隔开了上下黑格，所以每条垂直线索只给出若干个长度 1 的块。在一列中试填时，黑格总数通常还能由多个位置补足。相邻两列的黑格数量**之差**却能排除大量摆法。乌龟逐条处理行列，再试填单格；这批题把决定性的信息放在相邻两列必须共同满足的条件里。

筛选阶段使用了从自己第一轮 C++ 求解器改出的通用穷举程序。它按普通数织规则搜索，记录首次找到解前的单行计算量，并继续搜索其他解。只从至少有一种等价布局被完整穷举且计数为 1 的种子中选题。镜像、转置保持解的一一对应；本构造的全白隔行还允许重排活动行，因为各列黑格始终彼此隔开、总数也保持不变。多种布局的搜索量用于筛选，所有最终文件另行接受上述端点证明。

## 自测

选手包的 `检查.py` 确认 120 道题的答案都满足线索，共 79 种尺寸。`generate.py --verify-only` 逐题从公开线索重建了唯一解。另在空目录中重新生成整套文件，题目和答案均逐字节一致。

本次 Linux 云环境只对定稿题集运行了一次选手包的 `测速.py`。它报告整包 **93.7601 秒**，乌龟解出 **119 道**，另有 **1 道达到上限或未答完**。通用穷举程序的搜索量高估了乌龟在这批题上的耗时。
