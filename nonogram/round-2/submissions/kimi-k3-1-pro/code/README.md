# 第二轮出题说明

## 生成方法

`gen.cpp` 是单文件 C++20 出题器，仅使用标准库。它生成确定种子的随机黑白网格，根据网格计算全部行列线索，再用独立实现的数织求解器评估难度并证明唯一解。

最终生成命令（PowerShell，在本提交目录执行）：

```powershell
g++ -O2 -std=c++20 -pthread gen.cpp -o gen.exe
.\gen.exe 50000 8 15 25 50 8 2000 100000 1 20
.\gen.exe variants 8 8 160
.\gen.exe variants 8 8 300
.\gen.exe variants 8 8 300
.\gen.exe variants 8 8 300
.\gen.exe variants 8 8 800
```

参数依次为：候选数、线程数、最小尺寸、最大尺寸、黑格百分比、随机种子、首解分支预算、唯一性证明分支预算、最低分支数、最低试填数。程序并发评估候选，按首解难度排序，输出前 120 道到 `题目.txt` 和 `答案.txt`。

原始批次得到 557 个达到门槛且已证明唯一的候选。随后 `variants` 命令读取当前最难的 8 道题，分别生成随机行排列和列排列，重新评估难度并覆盖输出前 120 道。各轮参数中的 160／300／800 是每个基题的排列数；实际共执行一轮 160、三轮 300 和一轮 800。最终一轮从 6400 个排列中得到 471 个可完整评估实例，再取前 120；入选末位分数为 5312，显著高于此前版本。

## 为什么这些题难

乌龟在两色试填不动点之后仍需要按收益选格搜索。出题器专门筛选首解就需要分支或大量试填的实例，排序分数为：

```
首解试填次数 + 1000 × 首解分支节点数
```

这些实例的单线传播不能确定答案；大量两色试填和较深的错误分支会直接增加 Python 乌龟的工作量和回溯成本。题集包含不同尺寸、矩形与方形实例，不依赖固定题号或答案硬编码。

## 唯一解保证

唯一性检查与难度筛选是分开的两个阶段：

1. 首解阶段若找到的网格与生成网格不同，立即知道至少有两解，丢弃。
2. 对首解吻合且达到难度阈值的候选，重新从空盘面执行完整搜索。证明阶段不使用试填捷径，而是进行单行精确传播和完整线排列枚举，继续搜索第二个解，不会在找到原答案后停止。
3. 只有搜索完整结束、解数恰好为 1、没有触及分支预算，并且找到的唯一网格等于生成网格的候选才会入选。
4. 排列阶段只对上述已证明唯一的网格重新编号行和列。若排列后的题存在另一个解，逆排列就会给出原题的第二个解，所以排列前后解集合一一对应，唯一性无需重新近似估计。变体答案也经过首解回代核对。

单行推理使用前缀／后缀动态规划求精确 arc consistency；分支枚举覆盖每条候选线的全部排列。因此全部基题均有程序穷举证明唯一解，最终排列题则通过显式双射继承该证明。答案文件保存对应的原始／排列网格，并另外用选手包的 `检查.py` 核对格式和全部线索。

## 文件

- `题目.txt`：120 道题，题号为 `k2-1` 至 `k2-120`。
- `答案.txt`：对应的 120 份完整答案。
- `gen.cpp`：出题器与独立唯一性证明器源码。
- `worklog.md`：实际系统时间与测试记录。
