## 算法

每行/列用 64 位掩码记录已知黑格 `F` 和已知白格 `E`，所有推导都在掩码上完成。

**1. 行的精确求解（line solving）**
对一条长 L、线索块 `cl[0..k-1]` 的线做两个方向的 DP：

* 正向 DP `fw[i]`：第 i 块的起点集合，要求 blocks 0..i-1 能放在 s 之前（间隔至少 1 个白格、间隔里没有已知黑格、所有已知黑格都被覆盖、任何块都不压到已知白格）。
  转移用 `prefF`（已知黑格前缀计数）O(1) 判断间隔里有没有黑格；对每个候选起点取 `fw[i-1]` 中 ≤ s-1 的最大结束位即可判定，O(k·L)。
* 反向 DP `bw[i]`：把线反过来、在反线索上做同样的正向 DP，再映射回原坐标，得到「第 i 块之后的各块都能放下」的起点集合。
* `valid[i] = fw[i] & bw[i]` 就是第 i 块在完整解中所有可能的起点。
* 由 `valid[i]` 推出：
  * **必黑** = 所有可能起点覆盖范围的交集 `[max, min+c-1]`；
  * **必白** = 任何可能起点都不覆盖的格子；
  * 若已知黑格落在所有可能覆盖范围之外，或某块没有任何可能起点，则判定为矛盾。

该推导对小规模线用暴力枚举全部填法做了 30 万组随机对拍（`L ≤ 18`，`k ≤ 5`），结论与暴力完全一致。

**2. 传播**
脏行/脏列队列：任何格子状态变化，就把垂直方向的线重新入队；一条线推导出新格子后自己也重新入队（新的知识可能给出更多推导），直到队列空。

**3. 搜索**
传播停住且还有未知格时：

* 先算所选线的 DP。如果这条线的可能解很少（各块候选起点数之积 ≤ 64），就枚举它的全部合法填法，逐个整行/整列地分支；
* 否则猜一格：选未知格最多的线里「被最多放置覆盖」的那一格（最可能是黑格），先试黑再试白。

分支状态放在全局数组里（`gstack`/`gdp*`/`gsols`），搜索深度上限 2100，避免深递归爆栈。

## 练习题自测

* 合成题（12×12，随机 50% 黑格，自带真值）：5/5 解出且网格全部满足线索。
* 官方练习题 `练习题.txt`（24 道，40×40 ~ 45×45）：逐题解出并用独立脚本按线索校验，**结果与用时见 `worklog.md`**。

评分只按网格是否满足该题全部线索判定，多解的题交任意一个解都算对，所以本程序只需要尽快找到任意一个合法解。
