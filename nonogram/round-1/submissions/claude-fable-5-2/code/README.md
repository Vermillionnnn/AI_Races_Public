# claude-fable-5-2 — 数织求解器（round-1）

单个源文件 `solver.cpp`，C++20，只用标准库。

## 编译和运行（PowerShell）

编译（即 `AGENTS.md` 里的 g++ 命令）：

```
g++ -O2 -std=c++20 solver.cpp -o solver.exe
```

运行：

```
cmd /c "solver.exe < input.txt"
```

裁判自测：

```
py -3.13 裁判/judge.py --cmd "solver.exe" --with-baseline
```

代码也按 MSVC 可编译来写（`cl /O2 /std:c++20 /EHsc /Fe:solver.exe solver.cpp`），但我只在 Linux g++ 13 上实际编译测试过，Windows 上两种编译器都没有机会实测。

## 算法

1. **位并行的精确行求解**。每条线用两个 64 位掩码表示（已知黑、已知白）。对线索做前向 DP：`F[j]` 是"前 j 块能放进前缀 [0,i)"的所有 i 的位集；块的合法起点用移位与运算一次算出，"块后面接若干白格"的延伸用一次加法进位（`(NB + E) ^ NB`）完成，没有逐格循环。把线翻转后做同样的 DP 得到后缀集合 `G[j]`。两者相与得到每块的可行起点集合，再得出"可以为黑""可以为白"的格子，从而得到这条线上所有能确定的格子（结果是精确的，不是近似）。
   - 同一条线里长度相同的块共用"连续 L 个可黑格"的掩码；各块覆盖范围按长度分组后一次合并。
2. **传播**。行、列脏位掩码，反复解脏线直到不动点。
3. **试填（probing）**。对每个未知格分别假设黑、白并传播：一边矛盾则定为另一边；两边都不矛盾则取共同推出的格子。
   - 试填顺序：已知邻格多的格子先试（更容易出矛盾）；一轮里有 16 次进展后顺序已经过时，重新排序开始下一轮。
   - 每格的试填结果带上它读过的行、列集合缓存下来；只有这些线发生变化时才失效重试（精确失效）。DFS 子节点继承缓存。
   - 只影响本行本列、没有进一步推导的"平凡试填"不复制状态，直接用两次行求解判定。
4. **DFS**。试填后仍未解完时，选 `(黑分支推出格数+1)×(白分支推出格数+1)` 最大的格子分支。
5. **行求解缓存**。每个工作线程一个直接映射哈希表，键为（线编号, 黑掩码, 白掩码），试填里大量重复的行求解直接命中（约三分之二的调用命中）。
6. **两个工作线程**。主线程逐题读入并入队，读到一道完整的题就可以开始解；两个线程各解不同的题，输出整段加锁、每题 flush。
7. **输出前校验**。每个答案输出前都按全部线索重新核对，核对不过或输入格式异常就输出 `UNSOLVED`，不冒险答错。

## 自测结果（练习题 24 道）

测试机是我工作用的 Linux 容器（4 核，g++ 13.3，`-O2 -std=c++20`），不是比赛用的 Windows 云电脑，绝对时间仅供参考。

| 版本 | 解对 | 裁判总用时 |
|---|---|---|
| 基准程序（`--with-baseline`，跑 1 遍） | 24/24 | 39694.9 ms |
| 第一版（同一次运行） | 24/24 | 185.3 ms |
| 最终版，第 1 次 `--repeat 3`：39.8 / 38.1 / 51.4 | 24/24，答错 0 | 中位 39.8 ms |
| 最终版，第 2 次 `--repeat 3`：46.8 / 39.8 / 41.0 | 24/24，答错 0 | 中位 41.0 ms |

裁判测得的时间在这台容器上波动不小（同一个程序单遍在 38–51 ms 之间），所以最终版大约是 40 ms 上下。基准程序只在第一版时一起跑过一遍；"最终版约为基准的 1000 倍"是用不同运行的结果相除得到的粗略数字，不是同一次运行里测的。

单线程跑完 24 道练习题（含进程启动，9 次取最小）：第一版约 265 ms，最终版约 63–67 ms。

另外检查过：CRLF 换行的输入结果一致；全空线索（`0`）、线索自相矛盾的题、被截断的题分别输出正确答案、`UNSOLVED`、`UNSOLVED`。

## 已知局限

- 没有在 Windows / MinGW / MSVC 上实际编译运行过。
- 边长上限按 62 处理（题目是 40–45），超过的题输出 `UNSOLVED`。
- 没有设置单题超时。练习题最慢一道只有几毫秒，但我用自己生成的、**不保证唯一解**的纯随机题做压力测试时，300 道里 2 分钟只答出 28 道（都正确），有两道各卡住一个线程超过 2 分钟没解完——那是约束很弱的多解题上的深度搜索，不是死循环。正式题如果真的只有唯一解且和练习题同分布，不会遇到；万一遇到，那道题会一直占用一个线程直到总时限，其余题由另一个线程继续解。
