# 数织（Nonogram）高速求解器

## 编译与运行命令

### Linux / Bash（当前自测环境）

```bash
# 编译（GCC 12.2.0 开启 O3、本地架构指令集与 LTO 优化）
g++ -O3 -march=native -flto -pthread solver.cpp -o solver

# 运行
./solver
```

### Windows PowerShell（正式比赛环境）

```powershell
# 编译
g++ -O3 -march=native -flto -pthread solver.cpp -o solver.exe

# 运行
.\solver.exe
```

### 使用裁判程序自测

```bash
python3 裁判/judge.py --cmd "./solver" --repeat 3
```

## 核心算法与性能优化

1. **64 位全位运算单行推导器（$O(k)$ 硬件进位状态传播）**
   - 题目尺寸在 $40 \times 40$ 到 $45 \times 45$ 之间，单行/单列状态完全装入一个 `uint64_t`。
   - **区间零检查倍增预计算**：每次调用 `solve_line` 时仅需 5 次位移或运算预计算长度为 $1, 2, 4, 8, 16, 32$ 的白格覆盖掩码，之后每个线索块 $c_j$ 仅需一次位移与或运算即可在 $O(1)$ 时间内筛出不含已知白格的合法起点集。
   - **硬件加法进位正向传播**：利用二进制加法进位特性 `r = S | ((free + (S & free)) ^ free)`，仅用 4 条 CPU 整数指令即可一次性将上一块合法终点状态集合 `S` 沿所有可填白格区间（`free = ~known1`）向右传播至首个必黑格屏障。
   - **倍增掩码反向传播与完备必黑/必白格推导**：反向遍历线索块，通过 6 步对数倍增位移计算反向可达掩码，同时精确统计所有可被黑块覆盖的位掩码 `all_black` 与所有可作为白格间隙的位掩码 `all_white`，取反后一次性得出当前行/列全部新增必黑格与必白格。

2. **位掩码脏队列交叉传播（Bitmask Dirty Queue）**
   - 使用两个 `uint64_t`（`dirty_rows` 和 `dirty_cols`）代替传统的队列数据结构维护待更新的行与列。
   - 当某行推导出新增必黑/必白格 `nw = new1 | new0` 时，直接通过 `dirty_cols |= nw` 在一条指令内标记所有受影响的列，并通过 `__builtin_ctzll` 仅遍历新增位更新列掩码与增量已解格计数 `solved_count`。

3. **自适应前瞻试探（Adaptive FP1 Probing）与公共推导合并**
   - 当单行传播达到不动点但网格尚未解完时，对未定格按所在行列剩余未知数及四邻域已知格数量计算优先级，编码为单个 `uint32_t` 后使用 `std::partial_sort` 取前 $K$ 个候选格（根节点 $K=240$，深层节点 $K=44$）进行假设试探（分别试填 `1` 和 `0` 并传播）：
     - 若某分支引发矛盾，立即固定另一分支的值；
     - 若两分支均合法且均产生额外推导（`g1 > 1 && g0 > 1`），取两分支结果的交集（`(st1.row1 & st0.row1)` 与 `(st1.row0 & st0.row0)`）合并回当前棋盘并继续传播；
     - 若未触发矛盾或合并，按双分支传播收益乘积 `g1 * g0` 选出最优分支变量，并**直接复用试探阶段已传播完成的子状态**进入下一层 DFS，避免在分支节点重复执行传播。

4. **流式输入与双线程工作池并发调度**
   - 主线程流式读取 `PUZZLE`，一旦读完一道完整题目立即推入任务队列并唤醒工作线程，满足裁判先发一题热身、收到答案后再发正式题的交互要求。
   - 针对比赛限定 2 个逻辑处理器的规则，启动 2 个工作线程并行取题求解；输出时通过互斥锁保证单题 `SOLUTION <id>` 与网格连续完整输出并立即 `flush`。
