# 任务：数织求解程序速度赛

写一个数织（nonogram）求解程序。正式比赛时，所有选手的程序在同一台机器上解同一批题，**先比解对几道，再比总用时**。题目不难解，比的是谁的程序快。

## 选手包里的文件

| 文件 | 内容 |
|---|---|
| `agent.md` | 本文件：任务、比赛规则、运行环境、时间、交付 |
| `格式.md` | 数织规则，题目和答案的纯文本格式 |
| `练习题.txt` | 练习题，和正式题同一个出题器、同样的尺寸和难度分布 |
| `裁判/` | 裁判程序和一个基准程序。按正式比赛的流程运行你的程序、判对、计时，并在同一台机器上和基准程序对比。**只运行，不要打开或阅读这个目录里的文件** |

## 正式题

- 随机生成的黑白格，不是图案题。黑格约占一半。都是正方形，边长 40 到 45 之间，尺寸和难度分布与 `练习题.txt` 相同。
- 每道题都**只有一个解**。
- 正式题保密，和练习题不重复。把练习题的答案写进程序没有用。

## 程序怎么运行

题目和答案的格式见 `格式.md`。在此基础上：

- **一次运行解完所有题。** 程序启动一次，从标准输入一道接一道读题，读到文件尾就退出。
- **读到一道完整的题就开始解，不要等读完全部输入。** 裁判分两批发题：先发几道热身题，等它们的答案全部收到，再发正式题并关闭输入。等读到文件尾才开始解题的程序会卡在第一批，判为全部未解。
- **每解完一道就输出这道题的答案，并立即 flush。** 答案的顺序可以和题目不同，但每道题只能回答一次；同一道题回答两次，以第一次为准。
- 一道题的答案必须连续完整：`SOLUTION <id>` 和后面的网格之间不能夹别的输出。用多线程时注意加锁。
- 解不出的题输出 `UNSOLVED <id>`。标准输出只写答案和可选的统计行，调试信息写到标准错误。

## 计分

1. **解对几道。** 判对只看网格是否满足这道题的全部线索。
2. **答错扣分。** 答错比不答更糟：每道答错的题，在解对数里再扣 1 道。没把握的题宁可输出 `UNSOLVED`。
3. **总用时。** 从裁判发出正式题开始，到最后一道正式题的答案到达为止，由裁判在程序外面测量。进程启动、热身题不计时。整套题跑 3 遍，取中位数；相差 2% 以内算平手。
4. **总时限**很宽松，只防止程序卡死，超过就终止程序。已经输出的答案照常判分，没输出的算未解，所以一定要每道 flush。

## 运行环境

Windows 11 云电脑：8 个虚拟处理器，16 GB 内存。

- 语言自选，只能用标准库，写成一个源文件。
- 比赛时程序只能用 2 个逻辑处理器：裁判用 CPU 亲和性限定，线程数不限，但同一时刻最多两个线程在跑。
- 内存不超过 4 GB。不联网，不读写题目以外的文件。

已装的编译器和解释器，以及开优化的编译、运行命令，见仓库根目录的 `AGENTS.md`。比赛时就用那里的命令编译。

## 自测

用选手包里的裁判程序，按正式比赛的流程跑练习题：

```
python3 裁判/judge.py --cmd "<运行你的程序的命令>" --with-baseline
```

Windows 上把 `python3` 换成 `py -3.13`。裁判先发一道热身题，收到答案后再发全部练习题，从那一刻开始计时；程序限定在 2 个逻辑处理器上；最后列出解对几道、总用时和每道题的用时。

`--with-baseline` 会在同一台机器上运行一个基准程序作对比（需要装了 node），让你知道自己的程序在这台机器上是快是慢。基准程序没有特别优化，正式比赛时它也会和大家一起跑。不加这个选项就只跑你的程序；`--repeat 3` 跑三遍取中位数，和正式判分一样。

## 时间

完成时限写在开场消息里。用系统时间计时，不要凭感觉估计用了多久。

- 查时间的命令：PowerShell 用 `Get-Date -Format 'yyyy-MM-dd HH:mm:ss'`，Git Bash 用 `date '+%F %T'`。不要在 cmd 里用 `date`。
- 第一步先查时间，算出截止时间，记进工作日志。之后每完成一个阶段也查一次。
- 工作日志里写的每个时间，都必须照抄查时间命令的实际输出。
- 剩余时间还多就继续优化和测试，不要提前交卷。对手是其他强大的 AI，提前交卷没有任何好处。
